# QDL v1 formal acceptance plan

Specialist 7; research only, 2026-10-04. Read `AGENTS.md`, `docs/QDL-V1-WORKPLAN.md`, the semantics/API/stdlib/security/City reports, existing `spec/*.qnt`, and the relevant Lean operational, constructor, integration, ranch and display models. Only this report and `formal-prototype.lean` were added. No production implementation, credentials, git mutation or live action.

Release a bounded declared-thought language with a precise acceptance contract. Prioritize source-preserving invocation, checked references, bounded result/failure records and atomic replayable local commits. Existing proofs are useful abstract guarantees; none establishes refinement of the JavaScript compiler/interpreter, codec, persistence driver or renderer. A release can require checked local proofs plus implementation correspondence fixtures without claiming complete type soundness or exactly-once external execution.

## Definitions to freeze before implementation

Use the closed stable envelope and separate `input(name,type)` from immutable `literal(value,type)` proposed in `language-semantics.md`. Resolve the runtime/API report's literal-default alternative in favor of explicit ports, exact required bindings and explicit null for optional values. Defaults are an authoring operation before source identity is assigned, never an import/invocation rewrite. Likewise, add occurrence to the API's host invocation selector; node ID alone is ambiguous across repeats. These are integration recommendations, not implemented decisions.

Define the following shared terms once in the normative registry manifest and executable validators:

* `Source`: complete admitted declaration, graph/types/literals, authored design, repeat count and semantic pins. `Canonical(Source)` is the frozen admitted-data serialization, not arbitrary `JSON.stringify` on untrusted objects. Source equality is equality of canonical bytes; a digest is a lookup identity under the stated collision assumption, never authorship or authority.
* `Pin`: source digest, language/profile, registry ID plus immutable registry digest, canonicalization profile. A package version or legacy `version:1` is insufficient. Fix whether the registry digest is inside source or its mandatory envelope; every run/import/restore must verify the same pin.
* `Bindings`: a finite closed map with exactly the declared port names; values satisfy structural types, normalized symbolic units and runtime refinements. `InputDigest` covers canonical effective bindings. External revisions/times/evidence categories are supplied values, never ambient reads.
* `Occurrence`: index 0–7 within a run. Semantic identity is `(Pin, InputDigest, occurrence)`; caller request/run IDs and timestamps are metadata. Equal semantic identity yields equal results and ordered traces; independent fresh runs may still allocate different storage IDs.
* `Eval`: deterministic authored-ready-order DAG evaluation with a bounded trace and `ok(outputs, stagedSimulations)` or `failed(diagnostic, completedTrace)`. Runtime checks may fail on admitted typed bindings, for example overflow, empty filtered mean or a scheduling cycle. Well typed must therefore mean typed success **or a specified failure**, not total successful evaluation.
* `RequestKey`: `(hostSession, authenticatedPrincipal, requestId)` plus the complete canonical request including pins, inputs and occurrence selectors. Store canonical request bytes or defend against digest collision; changed request content conflicts. Replay lookup precedes fresh revision validation.
* `SemanticState`: admitted artifacts, run records, authoritative request/admission ledgers, world revision and collaboration state. `ViewState`: phase, camera, pause, selection and replay cursor. Persisted source includes authored design; transient display state does not.

Public thought declarations are authored records. Their integrity means unique IDs, valid references and source-bound interpretation; it proves neither factual truth nor extraction of private model reasoning. Public City guides/captured strings motivate synthetic fixtures only, as recorded in `city-context.md`.

F4 semantic failure can itself be a valid committed failure **record/response** under F5; its occurrence has no published simulations. This differs from a storage/schema/response-capacity refusal, which commits no semantic state. A semantic cap failure must have bounded reserved diagnostic space; do not exhaust the cap then attempt to allocate an unbounded error envelope. Canonical byte accounting includes escapes and UTF-8, not string `.length`.

## Pending and unknown: two separate protocols

The pure `reconcile` reducer implements supplied-history assessment, not provider dispatch. Its state precedence follows `stdlib.md`: unknown, pending, completed, exhausted, ready, retryable; requested zero completes only if no unresolved attempt exists. The Lean prototype's `mayRetry` is only the necessary pending/unknown blocker, **not** the complete reducer or authorization rule. Distinct source strings/evidence categories do not prove independence or authoritative world confirmation.

An optional external host has a separate `prepared → dispatched → completed|failed|unknown` ledger. After dispatched, a timeout/crash/cancel must not create a fresh dispatch; unknown can resolve only through the adapter's matched authoritative reconciliation. Dispatch identity includes `(Pin, recordId, occurrence, nodeId, payloadDigest, capability, RequestKey)`. Durable dispatched intent precedes the call: a crash before actual provider submission can conservatively remain unknown. Do not infer safety from absence of acknowledgement. Repeated lookups/reconciliation are observations, not new attempts.

Simulation-only v1 can pass acceptance with no host invocation API and all callback counters zero. If a real adapter ships, additionally model request replay/unknown resolution in Quint and test provider-specific idempotency, crash points and receipt matching. QDL proofs cannot establish the provider's exactly-once contract. Source `allowed`, imported `completed` JSON, saved plans and parent history never supply host authority.

## Lean and Quint: achievable division of work

**Lean:** reusable structural lemmas and induction independent of bounded search: source/port nonmutation, reference closure under transformations, receipt immutability across sequences, typed finite outcome shape, passive view projections, atomic record/world invariants. Reuse `QDL.Quine`, `Semantics`, `Integration`, `Ranch` and display provenance results with explicit hypotheses. Constructor self-emission currently abstracts task execution as a total payload function; do not apply it as a theorem that new input-dependent fallible tasks always succeed. Keep source recovery verification separate from task success. Existing exact rationals/integers and real geometry do not prove JS binary64 results or GPU rendering.

**Quint:** finite lifecycle interleavings and counterexamples: proposal cancellation/late responses, request replay/conflict/full ledgers, response loss, CAS races, batch commit boundaries, pending/unknown observations, two-parent admission and stale pins. Start with two principals/sessions, two keys, two attempts, two occurrences, two registry tokens; include mismatched identities, one capacity boundary and every crash transition. Add negative controls for partial commit, unknown auto-redispatch, forgotten pin and eviction reopening a consumed key. Existing finite models omit many real graph/value/transport details.

Use deterministic Quint scenarios first, then bounded seeded exploration. Record backend, initial state, bounds, seed and samples; TypeScript `quint run` is sampled simulation, **not exhaustive model checking**. If using an exhaustive backend later, record actual covered state space/depth and liveness/fairness assumptions. Absence of sampled violations is useful bug-finding evidence, not a universal safety proof. No liveness guarantee that an unknown provider eventually resolves, a mission succeeds or all ranch participants meet belongs in release claims.

For correspondence, freeze `ProjectJS(state)` and map each production operation to a model transition. Replay generated traces against the implementation and compare pinned state/results/errors, with independent expected outcomes; do not merely regenerate expected answers from production code. Unknown status, receipt IDs, occurrence and byte limits must survive the projection. Explicitly exclude codec internals, parsing, binary64, storage and transport where tokens stand in for them. `verify-ranch-model.cjs` is an existing bridge to inspect/extend during integration, not evidence rerun by this assignment.

## Checked prototype and evidence ledger

`formal-prototype.lean` imports installed `Std` only. It has 13 named theorems and no `sorry`, custom axioms or unchecked native evaluation. It models an unbounded mathematical receipt function without eviction and admitted canonical request strings; response/world are Nat tokens. `ready=true` assumes all staging/schema/size/storage preconditions and atomic replacement. Those assumptions require production tests. In particular its raw `commit` helper has no duplicate guard; the proof boundary is `execute`, so production must prevent direct bypass.

Checked claims: occupied request keys leave state unchanged; exact replay returns the recorded response; changed content conflicts; unready fresh requests refuse; fresh execution installs world/revision/receipt together; other-key execution preserves occupied receipts; immediate replay after commit cannot commit again. `receipt_monotone` iterated over execute transitions gives permanent key occupancy and therefore at most one local fresh commit per key. Observation lemmas show terminal immutability and nondecreasing per-attempt confirmed contribution under `CanObserve`; aggregate deduplication, ordering and complete-history validation remain proposed. Failure/publication and passive-render lemmas check their deliberately small definitions, not an evaluator/renderer refinement.

## Integration order and release claim

1. Freeze source/pin/port and diagnostic schemas plus registry semantics. Implement one validator across entry points; add F1–F3/F8 fixture gates.
2. Stage bounded occurrence results and failure records; stage response and durable replay receipt before committing. Add F4–F6 boundary/fault/concurrency fixtures and extend Quint session transactions. Promote the isolated Lean ledger lemmas only after finite budget/expiry semantics are modeled; never silently discard keys.
3. Revalidate ranch child declarations/types/pins after composition; add F7/F9 passive/reference/atomicity checks and trace correspondence. Include actual installed SDK and browser/transport serialization evidence.
4. Run pinned Lean proof-dependency/fixture audits, all deterministic model tests, recorded bounded exploration and production conformance tests. Any required gate still proposed means the production guarantee remains incomplete. If adapters are omitted, explicitly declare simulation-only.

Acceptable release wording: “A bounded, source-pinned declared-thought language with validated typed inputs, finite recorded outcomes and simulated actions; abstract safety contracts kernel-checked and lifecycle models tested, with documented implementation conformance evidence.” Add atomic durable replay only when the driver/fault tests pass. Do not claim verified thoughts, complete JS/type/codec refinement, historical authorship, guaranteed mission success or exactly-once external actions.
