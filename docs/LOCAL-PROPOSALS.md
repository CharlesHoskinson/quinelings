# Local proposal adapter

`node scripts/create-server.cjs` serves this checkout at `http://127.0.0.1:8048/` and implements `POST /api/propose` for an explicitly enabled same-origin proposal service. `QUINELING_PORT` changes the local port; optional `QUINELING_MODEL` selects a model already available to the installed CLI. No keys enter browser assets or quines. Static supported syntax and typed plan import work without a model service.

**Current measured limit:** the installed Codex CLI 0.160.0 rejects this deliberately tool-disabled invocation because its Code Mode requires the disabled code-mode host. The live smoke therefore fails closed; free-form synthesis through this adapter has not passed. The compiler, local grammar and structured import remain usable. Do not describe this adapter as working arbitrary-English translation until a compatible tool-free proposer passes the smoke. Required isolation was not weakened to make a demonstration succeed.

The request is `{thought:string,data?:JSON}`. The response uses the compiler's `supported`, `clarify`, `unsupported`, or `inconsistent` status with diagnostics, assumptions and source map. Supported responses contain a complete typed intent that is validated again locally. The model receives the public intent schema and kernel contract, never repository or account files. Submitted thought/data are sent through the existing authenticated Codex CLI to its configured service when compatible; this is not an offline language model. Existing CLI account usage applies.

The server listens only on 127.0.0.1, requires exact Host and Origin for proposal requests, accepts one in-flight proposal, limits requests to 64 KiB and thoughts to 16,384 characters, and kills proposals after 120 seconds or client cancellation. Static serving excludes hidden paths, scripts, dependencies and proof/cache trees, and rejects symlinks outside the checkout. No CORS permission is granted. The invocation uses an empty temporary working directory, read-only sandbox, disabled shell/apps/plugins/browser/image/computer/agent/tool features, ignored user config and exec rules, no project documentation, no MCP servers, and ephemeral sessions. Unexpected tool events reject the response. Temporary final-output/schema files are removed. Model reasoning, prompts, CLI stderr and auth information are not logged or retained by the server.

`node scripts/create-server.cjs --self-test` passes host/origin rejection, static exclusions, request-schema checks, single-flight behavior and compiler-gated responses without a model call. `--smoke` explicitly attempts two real model calls: a supplied-data reduction outside local syntax, and missing-input clarification. The first currently fails on the CLI compatibility limit above, so no second call is made. Neither command runs a live external task.

[Official non-interactive Codex documentation](https://learn.chatgpt.com/docs/non-interactive-mode) documents JSONL events, ephemeral sessions, saved authentication reuse, ignored user config, read-only execution and structured final-output schemas. Those transport features do not prove correct interpretation; every proposal still crosses the same finite typed compiler.
