# Ranch robustness: adversarial admission and replay constraints

Proposal for convergence, 2026-10-04. This report owns only this file. It is a design and independent test specification, not an implemented ranch, completed audit, or formal proof. Reviewed `AGENTS.md`, `docs/RANCH-WORKPLAN.md`, `docs/PROGRAM-CONTRACT.md`, available semantics/genetics/social/biology/experience/visual proposals, root `core.js`, `kernels.js`, `thought.js`, SDK admission/schema code and regression tests. No credentials, deployment or shared changes were used.

## Recommendation

Treat every pairing, recipe, parent annotation and asynchronous candidate as untrusted inert data. Prepare offspring through a pure bounded builder; admit through one serialized transaction whose final guards cover world state and SDK storage. Run remains explicit. No view, world tick, preflight, preparation, admission, export or rejected request may execute `Q.execute`, `K.run` or an action calculation. Compiler refinement calculation of pure kernels is permitted, bounded and distinct from a task run. Existing SDK `compile` admits immediately; existing `reproduce` runs a same-source copy. Neither is a ranch preview/birth primitive.

For the first candidate prefer pure typed mating. If effectful recipient mating is included, adopt the semantics report's protected action/guard-ancestor rule and test it separately. Body-only variation of recovered source is a separate operation; task mating requires validated companion intent. Never silently convert failed task mating into a successful body-only child.

## Current facts and limits

- SDK `inert` rejects nonfinite values, accessors, unsafe keys, symbols, hidden properties, sparse arrays, cycles and nonplain records before cloning; `dispatch` closes request fields. New SDK methods and MCP/A2A schemas must preserve that boundary. In-process JavaScript Proxy traps are outside a reliable inert-data sandbox: `Object.getPrototypeOf` and enumeration can themselves invoke traps. Do not claim arbitrary hostile JS objects are safely inspected; accept parsed JSON at untrusted transport boundaries, and regard direct in-process callers as trusted host code.
- `ThoughtCompiler.compile` checks exact structural types and normalized symbolic units, unique outputs/IDs, reachability, cycles, refinements and eager effects under `choose`. `K.validate` checks finite graph structure but is not a replacement for typed compilation: it does not require unique outputs or output reachability, and its node ID restrictions are weaker. Recovery of a valid task constructor does not imply eligibility for typed mating.
- SDK admission reconstructs the complete canonical task constructor and requires exact source equality, graph/design validation, assembly anatomy and gesture. It hashes the whole source. Recovered source in a fresh Runtime has no reconstructed intent/contract/source map. Same-source companion conflicts are rejected; enriching an existing untyped artifact mutates storage.
- Current defaults: 128 artifacts, 256 execution records; config ceilings 1024/4096. Bodies cache once per artifact, not per phase. Source budget is 65,536 UTF-8 bytes; companion intent 128 KiB; graph 64 nodes, 16 outputs, bounded JSON collections/depth. These are different bounds, not a single total-memory guarantee.
- `run` evaluates the whole DAG in ready order. A local reversible Node probe selected a skipped action as the false branch of `choose` while an unselected true-guard action still produced one simulated receipt. The corresponding typed intent rejected `eager-effect` at `$.steps.2`. Another probe confirmed `L*s*s^-1` normalizes to `L`, while `mL` stays `mL`. These observations confirm existing behavior only.

Every refusal returns a bounded diagnostic with the relevant field/port path; canonical authoritative state, counters, parent energy, pending links, artifact metadata and admission ledger remain identical. Returning a diagnostic must not recursively echo an enormous attacker payload.

## Transaction, retries and cancellation

Prefer an immutable staged ranch-state root covering world, candidate/proposal, lineage, ledger and artifact storage. If SDK remains a separate mutable store, integration must expose a real validate-and-commit batch, rather than treating a world rollback as a rollback of `Runtime.#admit`. Current artifact enrichment is a concrete partial-commit risk.

Admission order: check existing successful request ID and payload; otherwise validate candidate, versions, freshness and parent epochs; validate all capacity/geometry/energy/metadata guards; construct the complete next state; recheck revision; swap once. A successful duplicate returns its original result even after proposal consumption, expiry or parent retirement. A different payload under the same ID refuses. New requests with expired proposals refuse. Resource refusals keep a still-fresh proposal retryable, with zero charges. Terminal cancellation clears pending proposal/candidate links atomically, without task execution.

Retain the proposed 128-entry successful-request ledger for the whole world session; when full, refuse new births rather than evicting entries and permitting old request IDs to charge again. Network response loss after commit is repaired through idempotent retry. This specifies in-memory atomicity only; process-crash durability would need persisted transaction semantics and is not established here.

## Bounded resources beyond population

Adopt the converged limits explicitly: 32 residents including eight nursery, 16 pairings, 32 proposals (ecology may impose the stricter 16 via one unresolved proposal per parent), eight prepared candidates, 128 derivations, 128 successful requests, 256 informational events. Source/lineage limits alone are insufficient: graph copies, harmonics, colors, intents, frames and result traces also consume memory. Bound aggregate serialized bytes per store, retained frame count and adapter response size; specify whether overflow rejects or drops informational events with a dropped count. Active proposals and idempotency entries must never be silently evicted.

Avoid unbounded caches keyed by phase, camera, tick or request ID. Compiled-body caches can key immutable artifact+generator version and have a stated cap; cached mesh frames need a separate small cap or no retention. The visual report identifies palette-keyed `comp.sprites` growth and proposes six quantized phases plus a 16 MiB accounted fallback pixel cap: stress changing recorded lens palettes and ensure eviction/disposal actually obeys that cap. Ceremony replay queues, GPU slots, pick entries and context-restoration retries also need explicit bounds. Eviction of geometry is safe; eviction of successful admission history is not. Bound pending async preparations and ordered command queues separately; abort must release their retained buffers when completion arrives. `AbortSignal` cancellation alone does not prove the provider stopped working.

The current eight-body CPU baseline is about 81 ms median / 107 ms p95 at minimum 4,000 samples per body. A 32-resident population bound does not establish smooth rendering. Introduce a global visible geometry budget and profile maximum residents/candidates/store occupancy. If full-owner anatomy requires 4,000 samples per visible body, reduce simultaneously visible detailed bodies or use a reviewed alternate view; do not claim that under-budget sampling preserves ownership.

## Independent acceptance tests and oracle discipline

1. **Passive boundary:** instrument `Q.execute`, `K.run`, action calculations, execution-record additions and external adapters. Perform 10,000 world ticks plus previews/admissions/frames/recovery. All task/effect counters stay zero; pure compiler calculations may occur. One explicit child Run makes one fresh execution record. An admitted action-bearing child's receipt count follows its own guard/repeats, never parent history.
2. **Independent child:** recover offspring source into a fresh Runtime with no parents/providers. Hand-computed mean `[10,20,30] L` replacing available `5 L` in budget-for-`12 L` yields `{allocated:12,remaining:8}`. Exact emitted source matches. Metadata/lineage is unavailable unless separately supplied; removing parents does not break child computation. Do not use parent cached outputs as expected fixtures.
3. **Atomic birth:** start at each resource boundary, especially 31 residents/seven nursery and full SDK metadata capacity. Fault injection covers every write boundary. Assert both parent energies, every store and counter exactly equal on refusal; successful birth has one child, one slot, one consumed proposal, one ledger result and exactly 30 charged to each parent. Check parent energy 49/50 and latch 19/20 explicitly.
4. **Deterministic replay:** use fixed explicit world ID/seed and command sequence. Compare canonical snapshots, recipes, proposal/derivation/source hashes and node maps across repeated fresh runs and different renderer schedules. SDK execution records use random UUIDs today: compare execution content separately, do not falsely promise byte-identical record IDs. Golden child hashes must be literal reviewed fixtures, not calculated by the same helper under test.
5. **Input boundary:** parsed malicious JSON with unsafe keys, unknown fields, huge multibyte strings, depth 25, 65-node graphs, 17 outputs, duplicate refs/IDs and nonfinite direct SDK values refuses predictably. Accessor fixtures increment a counter if evaluated: rejection leaves it zero. Give transport raw JSON a byte limit before parsing; schema validation after parsing cannot undo allocation already incurred.
6. **Oracle mutation:** deliberately weaken one guard in an isolated test copy: allow unilateral pairing, skip epoch validation, split charges, call Run from courtship, retain expired candidates, or sort using locale. Corresponding tests must fail. State snapshots and expected outcomes are constructed independently of implementation helpers; property tests cannot merely mirror the same remapping algorithm.

A small Quint model should cover mutual enablement, active-parent identity/epochs, deadline precedence, single pending proposal, unique slots, two-parent charge atomicity, artifact/lineage/resident correspondence and bounded idempotency. Include explicit unsafe-transition counterexamples. Geometry, source compilation, real byte counts, browser scheduling and adapter calls require implementation tests beyond that model.

Potential Lean obligations include effect-summary closure, namespace injectivity, preservation of repeated ordered ports, well-typed pure-slice substitution under stated refinement premises, and atomic-state invariants. They remain proposed obligations until actual Lean files compile without admitted proofs and their premises match the implementation. Structural substitution alone does not prove numeric refinements; unchanged source hashes do not authenticate authorship; sampled geometry does not prove envelopes; finite state does not prove fairness, useful offspring or browser performance.

## Convergence decisions the candidate must make

Resolve pure-only versus guard-protected effectful mating; choose a single store/transaction owner; pin compatibility/version fields and replay ordering; reconcile 32 versus 16 social proposals; set aggregate memory/queue/cache/view budgets; and define diagnostic names consistently across TypeScript/MCP/A2A/UI. Nine later independent audits should receive the actual candidate plus this attack matrix and report runnable evidence separately from suggested fixes. Failed model calls or commentary are not audits; proposed Quint/Lean work is not proved work.
