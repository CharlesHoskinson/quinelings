# Thought to lifeform: proposed experimental QDL update

Historical design proposal. For the implemented stable language, read [QDL 1](QDL-V1.md). Creation and Ranch policies retain their separately documented experimental status. The proposal below describes an earlier stage.

A Quineling should be a useful executable program with a distinctive, coherent mathematical body. The next QDL update should generate both new programs and new anatomy, rather than select a gallery specimen and recolor it. Beauty is a first-class acceptance criterion alongside meaning, reproducibility, and bounded execution.

This is an integrated design proposal, supported by isolated working experiments. The production validator does not yet accept the proposed anatomy or gesture fields. QDL remains experimental; this work does not freeze version one.

## The complete translation

```text
Free-form thought + supplied data
  → explicit intent, assumptions, units, and capability obligations
  → typed task IR with ordered ports and guarded effects
  → validated executable DAG
  → generated anatomical expression + gesture + ownership
  → constructor quine with complete authored design
  → mathematical animation
  → explicit execution and source-bound recorded values
```

Free text can propose any goal. A goal becomes executable when its meaning is sufficiently specified and its required capabilities exist. Ambiguity produces a focused clarification; unavailable operations produce named obligations. Neither produces a fabricated success. The initial compiler builds on current bounded kernels; extending the capability registry requires an implementation, types, resource/effect contracts, and tests.

A language model proposes intent or task IR. It does not bypass the compiler. GitHub Pages can run local deterministic recipes, the interpreter, and artifact import/export. Optional free-text synthesis uses a provider-neutral authenticated backend or local service; provider credentials stay outside browser assets.

ThoughtDocument, typed IR, executable source, artifact manifest, RunRecord, and ViewState are distinct artifacts. Original thought/provenance stays in the companion document by default. Exact source reproduction does not automatically reproduce external notes or prove agreement with arbitrary English. A future source-embedded intent contract must be designed deliberately.

## How new creatures are generated

Replace mandatory family selection with a bounded anatomical assembly grammar: regular spines, positive-axis chambers, attached appendages, hinged membranes, and closed loops. The existing ten families become examples/presets within a larger design space.

The skeletal attachment tree supplies physical hierarchy. The task DAG supplies actual computations and ordered dependencies. They remain separate. Every operation has an inspectable anchor and positive material territory; each material sample has one declared owner. Decorative tissue may repeat an owner but never invent a computation. A rendered crossing, loop, or joint adds no task edge or execution control.

Topology supplies broad traits: serial structure creates an axis, fanout creates attached branches, convergence creates chambers. At most three bounded low-frequency shape modes add individuality without overwhelming the silhouette. A deterministic aesthetic seed supplies restrained variation. It is derived from the pre-anatomy graph and explicit preferences, then the expanded anatomical expression is committed inside source. Phase and wall-clock state never enter identity.

Initial grammar limits are 16 components, attachment depth 4, four children per component, at most four active charts per component, and global budgets of 24,000 tissue samples plus 1,806 crest vertices. These budgets are per animal. Task dependencies remain inspectable up to the actual port budget; simplifying decoration cannot silently remove instructions or edges. Check the complete canonical quine AST against the existing 65,536-byte genome ceiling, including duplicated constructor payload.

## What makes them beautiful and alive in motion

Give each creature one dominant body, a small number of attached subordinate structures, generous negative space, and two to four luminous structural crests. Build the silhouette before adding fine tissue. A jelly gathers and contracts; a crown unfurls through its branches; a glider prepares, strokes, then lets its trailing structures recover. New anatomy chooses a suitable gesture from its structure rather than borrowing a universal wobble.

The initial authored gesture record contains a closed gesture kind (`gather`, `unfurl`, `glide`, `hover`), strength in [0,1], and four integer timing values summing to 1,000, each at least 100. Fixed pose templates use

```text
H(z) = 6z⁵ − 15z⁴ + 10z³,  0 ≤ z ≤ 1.
```

Matching endpoint poses and zero endpoint first/second derivatives provide smooth stage transitions. Pose, sockets, organs, tissue, and crests share hierarchical transforms. Rigid socket attachment does not by itself prove smooth watertight joins or global nonintersection. Weighted blends of invertible transforms can collapse; the first implementation should avoid unrestricted skinning.

Soft following tissue can use bounded analytic harmonic response when the driver is actually a finite raw-phase harmonic sum. Applying the same formula directly to phase-warped sinusoids does not establish the claimed ODE solution. Periodic and quasiperiodic modes have distinct contracts; deterministic seeking is required in both.

Antialiasing, frame transport, numerical sampling, depth buckets, and renderer choice are implementation policy, not new artistic sliders. Start with compiled rest geometry, reused buffers, stable material IDs, round tissue kernels, restrained crest underlight, and interleaved depth. Normalize optical weights when sample counts change. Canvas-first work should be measured before a WebGL migration; existing Node geometry timings do not establish browser frame-rate performance.

Colors retain their meanings. Operation roles remain fixed; scalar pigment reads only declared values from source-matched run records. Missing, stale, and invalid values remain explicit. Lighting reveals form rather than changing the implied result. Exact RGB genome bytes remain a separate lossless record.

## The website experience

The main flow is **Build → Watch → Run → Create verified copy**. Build proposes and validates meaning; Watch is pure presentation; Run computes an actual task result; a verified fresh copy reconstructs source and records any fresh execution.

Show the thought moving into an explicit program, then into its body. Inspection links a thought clause to a task node, its ordered ports, a material owner, and any recorded quantity. Derive explanatory sentences from the artifact contract/source map, not hard-coded gallery prose. Three bounded body candidates can share task semantics; selecting a different authored design changes source and invalidates old run associations.

Unresolved intent remains a labeled proposal. The default still pose must be complete and beautiful. Pause, keyboard inspection, reduced motion, and mobile layouts remain part of the core experience.

## Evidence already produced

- A new seven-node planter task passes independently specified output and edge cases, three fresh quine generations, direct/sampled wave recovery, RGB recovery, and 336 finite geometry samples. Its interpretation is manually authored; automatic English compilation is not implemented.
- Two additional route/queue examples pass current-kernel outcomes, guarded-action rejection, and three fresh generations.
- A compositional anatomy prototype emits three new connected structural studies and an anatomy expression owning every node of the validated planter task. It is a schematic compiler, not the production 3D renderer.
- Three assembly gaits pass 387 sampled poses with socket error zero and determinant error below 6×10⁻¹⁶ in the restricted numeric model. An isolated animated preview passes deterministic seeking, reduced motion, mobile layout, and source-preservation checks.
- A Lean research prototype kernel-checks quintic bounds, actual derivatives, endpoint conditions, and interval preservation without admitted proofs or project axioms. It is not a proof of the complete proposed compiler.
- Ten independent kernel outcome fixtures and two invalid-refinement cases pass. The 20-thought benchmark separately labels supported, ambiguous, unsupported, and inconsistent inputs. The automatic compiler and human aesthetic scores have not been evaluated.

## Implementation sequence

1. Build typed intent/task validation, capability recipes, unit/refinement checks, and transparent diagnostics. Generate new graphs from unseen combinations; preserve explicit conditional-action guards in the eager DAG.
2. Add source-authored assembly anatomy with trunk, chamber, and attached spine first. Validate ownership, sockets, resource ceilings, and exact source/genome identity. Add fins/loops after connected silhouettes pass visual review.
3. Integrate shared gesture transforms, regular primitive charts, stable sampling and coherent light. Extend Lean and Quint alongside the actual schema/runtime changes.
4. Connect the website translation and generation flow, source-bound run records, independent fixtures, and recovery. Keep provider-generated proposals behind the same compiler checks.
5. Evaluate meaning and beauty separately: blind thumbnail identification, complete motion films, connected-body inspection, stated-device performance, accessibility, and the intent benchmark. Mathematical safety does not prove visual quality or natural-language understanding.
