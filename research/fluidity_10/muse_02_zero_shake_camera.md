# Zero-Shake Cinema Camera & Framing Director

**Agent:** Muse Wonder Fluidity Agent 2  
**Scope:** `lorenz-flow`, `clifford-flow`, `toroidal-weave`, `recursive-julia`  
**Targets:** `designer8_quineling.js`, `designer7_cinema.js`  
**Cure in one line:** Never frame from instantaneous extrema. Frame from a frozen canonical volume computed once per specimen; move the camera only during specimen morphs, through a critically damped spring on `(cx, cy, cz, logSpan, θ)`, with continuous (unwrapped, low-passed) velocity and rotation everywhere else.

---

## 1. Why instantaneous extrema inject high-frequency phase-harmonic shake

### 1.1 The faulty coupling

The shake appears whenever code of this shape runs per frame:

```js
// ANTI-PATTERN — do not ship
let minX = Infinity, maxX = -Infinity, minY = Infinity, maxY = -Infinity;
for (const p of points) {
  if (p.x < minX) minX = p.x; if (p.x > maxX) maxX = p.x;
  if (p.y < minY) minY = p.y; if (p.y > maxY) maxY = p.y;
}
cx   = 0.5 * (minX + maxX);
cy   = 0.5 * (minY + maxY);
span = Math.max(maxX - minX, maxY - minY);
```

Four independent mechanisms turn this into camera shake:

**a) Extrema are order statistics, not smooth statistics.**  
The mean of a point cloud is a smooth function of the points; the max is not. `maxX(t)` is piecewise-defined: it equals whichever single particle is currently extreme. When the argmax particle changes — which on a chaotic attractor happens many times per second — the derivative `d(maxX)/dt` jumps discontinuely even though every particle moves smoothly. The camera inherits a **C⁰-but-not-C¹** signal: position is continuous, velocity is a spike train.

**b) The extreme particle is the worst particle.**  
On `lorenz-flow` and `clifford-flow`, the point sitting at the bounding-box edge is disproportionately likely to be (i) a transient still falling onto the attractor, (ii) a particle in the high-velocity lobe-switching region, or (iii) numerical spray. The frame is therefore slaved to the *least representative, fastest* sample in the system. One escaping particle at 3× the attractor radius instantly inflates `span` by 3× and drags `(cx, cy)` halfway toward it — then the next frame it is gone or recycled, and the camera snaps back. That snap-back is the visible "breathing/pumping" artifact.

**c) Phase harmonics: the attractor's own frequencies leak into the camera.**  
A Lorenz trajectory crosses lobes quasi-periodically; a Clifford flow has strong spectral peaks at its map frequencies; `toroidal-weave` is literally periodic. The extrema sequence `maxX(t)` is a nonlinear (rectifying) function of the trajectory, so it contains the attractor's fundamental frequencies **plus their harmonics and intermodulation products** generated by the `max(·)` nonlinearity and by argmax switching. Coupling `span` to that signal amplitude-modulates the whole image at those frequencies. Because the display samples at 60 Hz, components above 30 Hz alias down into the 1–15 Hz band — precisely the band where human vision is most sensitive to jitter. The result is perceived as shake *even when each individual frame is perfectly rendered*.

**d) `span` and center fight each other.**  
`span` from `max(width, height)` switches which axis is limiting. At the switch, `d(span)/dt` changes sign structure abruptly, and because screen position is `(p − c) / span`, a jump in `span`-velocity is a jump in the velocity of *every pixel simultaneously*, in the opposite direction to the center motion. The two discontinuities rarely cancel; they beat against each other.

**Summary:** instantaneous extrema give the camera a discontinuous-derivative, outlier-dominated, spectrally-harmonic-ringing input. No amount of downstream smoothing fully cures it, because smoothing a spike train still leaves phase-lagged pumping. The input itself must be removed.

### 1.2 The invariant that fixes it

An attractor, by definition, has a **time-invariant support** (up to transients). `lorenz-flow` with fixed parameters lives inside the same bounded region at t = 10 s and t = 10,000 s. Therefore the correct framing is a property of the *specimen and its parameters*, not of any frame:

> **Framing is a compile-time constant per specimen. The camera's steady-state velocity is exactly zero.**

Motion is permitted only for one reason: the specimen changed. That motion is a designed transition, not a measurement.

## 2. Canonical bounding sphere / portrait box, computed once

### 2.1 Offline (compile-time / load-time) computation

For each specimen, run a long, seeded, deterministic probe trajectory **once** — at module load or in a build step whose results are baked into a table. Discard burn-in, accumulate robust quantiles (never min/max), and freeze the result.

```js
// canonical-frame.js — run ONCE per specimen, then frozen
import { createRng } from "./rng.js"; // seeded, deterministic

const TAU_MORPH = 0.45; // s — see §3

/**
 * Probe a specimen's invariant support.
 * spec: { seed, burnIn, samples, step(rng)->point|null, makePoint(rng) }
 * Returns a frozen canonical frame. NEVER call per frame.
 */
export function computeCanonicalFrame(spec) {
  const rng = createRng(spec.seed);
  const pts = [];
  let p = spec.makePoint(rng);

  for (let i = 0; i < spec.burnIn; i++) p = spec.step(p, rng);       // land on attractor
  for (let i = 0; i < spec.samples; i++) { p = spec.step(p, rng); pts.push(p); }

  // Robust per-axis quantiles — immune to transients and spray.
  const q = (arr, t) => arr[Math.min(arr.length - 1, Math.floor(t * arr.length))];
  const xs = pts.map(p => p.x).sort((a, b) => a - b);
  const ys = pts.map(p => p.y).sort((a, b) => a - b);
  const zs = pts.map(p => p.z ?? 0).sort((a, b) => a - b);
  const LO = 0.001, HI = 0.999;

  const box = {
    x0: q(xs, LO), x1: q(xs, HI),
    y0: q(ys, LO), y1: q(ys, HI),
    z0: q(zs, LO), z1: q(zs, HI),
  };

  // Bounding-sphere center = box center; radius = 99.9th-percentile distance.
  const cx = 0.5 * (box.x0 + box.x1);
  const cy = 0.5 * (box.y0 + box.y1);
  const cz = 0.5 * (box.z0 + box.z1);
  const dists = pts.map(p => Math.hypot(p.x - cx, p.y - cy, (p.z ?? 0) - cz))
                   .sort((a, b) => a - b);
  const radius = q(dists, HI);

  return Object.freeze({ cx, cy, cz, radius, box });
}

/** Derive the 2D portrait box (cx, cy, span) for a given viewport aspect. */
export function portraitBox(frame, aspect /* w/h */, margin = 1.12) {
  const { box } = frame;
  const w = box.x1 - box.x0, h = box.y1 - box.y0;
  // span = full vertical extent needed; widen if the box is wider than the viewport.
  const span = Math.max(h, w / aspect) * margin;
  return Object.freeze({
    cx: 0.5 * (box.x0 + box.x1),
    cy: 0.5 * (box.y0 + box.y1),
    cz: frame.cz,
    span,
    angle: 0,
  });
}
```

Key properties:

- **Quantiles, not extrema.** The 0.1%/99.9% cuts delete burn-in stragglers, lobe-switch spray, and Julia-set escapees by construction. Increasing `samples` tightens the estimate instead of (as with min/max) making it *worse*.
- **Deterministic.** A fixed seed means every user, every run, every machine gets the identical frame. No first-frame pop, no machine-dependent framing.
- **Frozen.** `Object.freeze` makes accidental per-frame mutation a loud error in strict mode rather than silent drift. Recompute only when parameters change — and then treat it as a specimen morph (§3), not a reframe.
- **3D-ready.** `cz` and `radius` give `toroidal-weave` and 3D projections a true bounding sphere: project the sphere, not the points, if a perspective fit is ever needed. The 2D specimens simply ignore `z`.

Recommended probe sizes: `burnIn ≥ 2,000` steps, `samples ≥ 60,000` steps for maps (`clifford-flow`, `recursive-julia`); for flows (`lorenz-flow`), integrate the probe with the same RK4/`dt` the renderer uses so the canonical frame describes the *simulated* attractor, not the idealized one.

### 2.2 The baked table

```js
// canonical-frames.js — generated once, committed, never recomputed at runtime
export const CANONICAL = Object.freeze({
  "lorenz-flow":     portraitBox(computeCanonicalFrame(LORENZ_SPEC),     16 / 9),
  "clifford-flow":   portraitBox(computeCanonicalFrame(CLIFFORD_SPEC),   16 / 9),
  "toroidal-weave":  portraitBox(computeCanonicalFrame(TORUS_SPEC),      16 / 9),
  "recursive-julia": portraitBox(computeCanonicalFrame(JULIA_SPEC),      16 / 9),
});
```

If aspect changes (resize, portrait phone), recompute **only** `portraitBox(...)` from the frozen sphere/box and morph to it via §3 — do not re-probe.

## 3. Critically damped spring — only for specimen morphs

### 3.1 Why critical damping, why τ = 0.45 s

A camera transition must be **C¹ continuous** (no velocity jumps), **monotonic-ish** (no overshoot — overshoot in `span` reads as a bounce), and **finite-feeling** (arrives and stops). The unique second-order system with all three properties is the critically damped spring, ζ = 1:

```
ẍ = ω² (target − x) − 2ω ẋ,        ω = 1/τ,  τ = 0.45 s
```

- ζ < 1 (underdamped) → overshoot → visible bounce. Forbidden.
- ζ > 1 (overdamped) → sluggish tail → the camera "swims" after arrival. Forbidden.
- ζ = 1 → fastest non-overshooting arrival. With τ = 0.45 s, the morph reaches ~95% in ≈ 3τ ≈ 1.35 s and is visually settled by ~2 s — long enough to read as a deliberate dolly, short enough to not block the next specimen.

`span` is integrated in **log space** (`s = ln span`) so the spring can never drive span negative and zoom speed is perceptually uniform (equal ratios take equal time). Angle is integrated on the **unwrapped** real line (§4.2).

### 3.2 The CameraDirector

```js
// camera-director.js
const TAU = 0.45;                 // s
const OMEGA = 1 / TAU;            // rad/s (per unit)
const SETTLE_POS = 1e-4, SETTLE_VEL = 1e-4;

function springStep(state, target, dt) {
  // One critically damped channel. Semi-implicit Euler: stable at frame dt.
  const accel = OMEGA * OMEGA * (target - state.x) - 2 * OMEGA * state.v;
  state.v += accel * dt;
  state.x += state.v * dt;
}

export class CameraDirector {
  constructor(initialFrame) {
    this.ch = {
      cx:    { x: initialFrame.cx,    v: 0 },
      cy:    { x: initialFrame.cy,    v: 0 },
      cz:    { x: initialFrame.cz,    v: 0 },
      s:     { x: Math.log(initialFrame.span), v: 0 },  // log-span
      angle: { x: initialFrame.angle ?? 0,     v: 0 },  // UNWRAPPED radians
    };
    this.target = initialFrame;
    this.morphing = false;
  }

  /** The ONLY way the camera ever receives a new destination. */
  morphTo(frame) {
    // Unwrap the angle target onto the branch nearest current angle (§4.2).
    const twoPi = Math.PI * 2;
    const cur = this.ch.angle.x, tgt = frame.angle ?? 0;
    const unwrapped = tgt + twoPi * Math.round((cur - tgt) / twoPi);
    this.target = { ...frame, angle: unwrapped };
    this.morphing = true;
  }

  /** Call once per rendered frame. Returns a plain {cx, cy, cz, span, angle}. */
  update(dtRaw) {
    if (!this.morphing) {
      // HARD ZERO-SHAKE GUARANTEE: no target change ⇒ no integration ⇒
      // the camera is bit-for-bit static. Nothing in the point cloud
      // can move it. Do not "helpfully" re-snap here.
      return this.snapshot();
    }
    const dt = Math.min(dtRaw, 1 / 30); // clamp tab-switch spikes
    // Substep for stability when dt is large relative to τ.
    const n = Math.max(1, Math.ceil(dt / (TAU / 8)));
    const h = dt / n;
    for (let i = 0; i < n; i++) {
      springStep(this.ch.cx,    this.target.cx, h);
      springStep(this.ch.cy,    this.target.cy, h);
      springStep(this.ch.cz,    this.target.cz, h);
      springStep(this.ch.s,     Math.log(this.target.span), h);
      springStep(this.ch.angle, this.target.angle, h);
    }
    if (this.settled()) {
      // Snap exactly onto the canonical frame and freeze again.
      this.ch.cx.x = this.target.cx;  this.ch.cy.x = this.target.cy;
      this.ch.cz.x = this.target.cz;  this.ch.s.x = Math.log(this.target.span);
      this.ch.angle.x = this.target.angle;
      for (const k in this.ch) this.ch[k].v = 0;
      this.morphing = false;
    }
    return this.snapshot();
  }

  settled() {
    const t = this.target;
    const near = (c, goal) => Math.abs(c.x - goal) < SETTLE_POS && Math.abs(c.v) < SETTLE_VEL;
    return near(this.ch.cx, t.cx) && near(this.ch.cy, t.cy) && near(this.ch.cz, t.cz)
        && near(this.ch.s, Math.log(t.span)) && near(this.ch.angle, t.angle);
  }

  snapshot() {
    return {
      cx: this.ch.cx.x, cy: this.ch.cy.x, cz: this.ch.cz.x,
      span: Math.exp(this.ch.s.x),
      angle: this.ch.angle.x, // keep unwrapped; wrap only at the trig call site if needed
    };
  }
}
```

### 3.3 Usage — the whole integration is three lines

```js
const camera = new CameraDirector(CANONICAL["lorenz-flow"]);

// On specimen switch ONLY:
camera.morphTo(CANONICAL["clifford-flow"]);

// Every frame:
const cam = camera.update(dt);
render(points, cam); // (p − cam.c) / cam.span, rotate by cam.angle
```

Note what is absent: no reference to `points`, extrema, or the simulation inside the camera. That absence is the cure.

## 4. Eliminating step-boundary lurches

### 4.1 `stepSurgeVel` velocity lurch

**Diagnosis.** A named surge velocity applied at step boundaries means the integrator (or the point advancer) does something like:

```js
// ANTI-PATTERN in designer8_quineling.js / designer7_cinema.js style
if (stepIndex !== prevStepIndex) {
  vel *= stepSurgeVel;          // ← discontinuous velocity multiplier
  prevStepIndex = stepIndex;
}
```

Whatever `stepSurgeVel` was compensating for (a perceived stall at segment joins), multiplying velocity at an instant creates a **δ-function in acceleration**: every particle's velocity jumps by the same factor on the same frame, so the whole cloud breathes outward/inward in one frame. On screen this is indistinguishable from a camera punch — and if any residual framing code reads the cloud, it becomes actual camera shake. It also breaks energy behavior differently depending on frame rate: at 120 Hz the surge fires half as often per second as at 60 Hz if steps are frame-counted.

**Cure.** Delete the multiplier. If a genuine speed change at segment joins is artistically wanted, express it as a *continuous function of continuous phase*, never of integer step index:

```js
// Continuous surge: a smooth pulse in phase space, identical at any fps.
function surgeFactor(phase /* continuous, radians or cycles */) {
  // smoothstep bump centred at phase = 0 (mod 1 cycle), width 0.18 cycles
  const t = ((phase % 1) + 1) % 1;
  const d = Math.min(t, 1 - t) / 0.18;              // 0 at centre → 1 at edge
  const bump = d >= 1 ? 0 : (1 - d * d * (3 - 2 * d)); // smoothstep, C¹ at joins
  return 1 + 0.25 * bump;                            // ≤ +25%, never a jump
}

// And low-pass the ACTUAL velocity so no caller can lurch it either:
class VelocitySmoother {
  constructor(tau = 0.12) { this.tau = tau; this.v = 0; }
  update(targetVel, dt) {
    const a = 1 - Math.exp(-dt / this.tau);  // frame-rate independent
    this.v += (targetVel - this.v) * a;
    return this.v;
  }
}
```

Rules:

1. `stepSurgeVel` and any `if (stepChanged) vel *= …` are removed, not retuned.
2. Speed modulation, if kept, is `surgeFactor(continuousPhase)` — phase advanced by `phase += ω·dt`, never by counting frames.
3. All externally-imposed velocity changes pass through `VelocitySmoother` (τ ≈ 0.10–0.15 s — fast enough to feel responsive, slow enough that its output is C⁰ in acceleration).

### 4.2 Rotation jumps

**Diagnosis.** Rotation discontinuities at step boundaries come from two classic sources, often combined:

```js
// ANTI-PATTERN A: resetting at segment joins
if (stepChanged) angle = 0;
// ANTI-PATTERN B: wrapped-angle lerp
angle += (targetAngle - angle) * k;   // target wraps 179° → −179°, camera spins 358°
```

**Cure.** Angle lives on the unwrapped real line for its entire life inside the camera/integrator. Wrapping is a *rendering* concern only, applied (if at all) at the `Math.cos/sin` call site — and trig does not even need it.

```js
// Advance rotation ONLY by integrating angular velocity. Never assign angle
// from a step index, a table, or a wrapped target.
class Rotor {
  constructor() { this.angle = 0; this.omega = 0; } // angle: unwrapped, monotone-capable
  update(targetOmega, dt) {
    const a = 1 - Math.exp(-dt / 0.15);       // smooth omega, no step lurch
    this.omega += (targetOmega - this.omega) * a;
    this.angle += this.omega * dt;            // C¹ continuous by construction
    return this.angle;
  }
}
// Render: const c = Math.cos(rotor.angle), s = Math.sin(rotor.angle); // no wrap needed
```

For camera-angle morphs, the unwrap-on-target logic is already in `CameraDirector.morphTo` (§3.2): the target is shifted by whole turns onto the branch nearest the current angle, so a morph from 350° to 10° travels +20°, never −340°. Because the spring (§3) is critically damped on that unwrapped value, angular velocity starts and ends at exactly the spring's smooth profile — zero at both ends, no lurch at the join.

When specimen switches also change the *spin rate*, route the new rate through `Rotor.update`'s low-pass rather than assigning `omega` directly; τ = 0.15 s makes rate changes inaudible to the eye.

## 5. Verification (falsifiable invariants)

Run headless against the real renderers; each test must fail on the old code and pass on the new:

| # | Invariant | Method | Pass criterion |
|---|-----------|--------|----------------|
| 1 | Zero steady-state shake | Fixed specimen, 60 s capture, record `cam` per frame | `max‖cam(t)−cam(0)‖ = 0` exactly (no morph ⇒ no integration) |
| 2 | No velocity δ at steps | Log per-particle `Δv` across step boundaries | No frame with `‖Δv‖` > 3× median frame `‖Δv‖` |
| 3 | Rotation C¹ | Log `angle`, finite-difference twice | `angle` monotone-smooth; no sample with `|Δ²angle|` > 5× median |
| 4 | Morph quality | Switch specimens, record `span(t)` | Monotonic approach, overshoot < 0.1%, settled (< 0.1% err) by 2.0 s |
| 5 | Frame-rate independence | Repeat 1–4 at 30/60/120 Hz sim | Invariants hold identically; surge/rotor use `dt`, never frame counts |
| 6 | Outlier immunity | Inject one particle at 10× radius for 1 frame mid-run | Camera unchanged (test 1 still exact); cloud renders, frame does not |

Test 6 is the decisive one: on the extrema-coupled code it produces a full-screen punch; on the canonical-frame code it is a no-op for the camera, by construction.

## 6. Summary

| Defect | Root cause | Cure |
|--------|-----------|------|
| High-frequency shake, breathing `span` | Camera slaved to argmax-switching order statistics of the cloud | Frozen canonical frame from seeded quantile probe (§2) |
| Outlier punch | Extreme particle is least representative sample | 0.1%/99.9% quantiles; camera never reads points |
| Phase-harmonic ringing | `max(·)` rectifies attractor frequencies into camera band, aliased at 60 Hz | Camera input is a constant; spectrum is DC only |
| `stepSurgeVel` lurch | Instantaneous velocity multiplier at integer step joins | Deleted; continuous `surgeFactor(phase)` + velocity low-pass (§4.1) |
| Rotation jumps | Angle reset / wrapped-angle lerp at joins | Unwrapped angle, integrated ω, unwrap-on-morph (§4.2, §3.2) |
| Transition bounce/swim | Ad-hoc lerps (under/over-damped) | Single critically damped spring, ζ = 1, τ = 0.45 s, log-span (§3) |

The design principle to keep: **the camera is a director, not a sensor.** It decides where to look from knowledge of the specimen; it never measures the frame it is about to draw.
