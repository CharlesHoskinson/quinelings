# Implemented creation workspace and generated renderer

The production entry is `create.html`. It loads the same bounded task runtime as the existing collection, with the new typed thought compiler, source-authored assembly generator and an isolated Canvas renderer. Existing `gallery.js` and its in-progress chromamapping work were not edited.

## What is implemented

- A thought composer with six actual supported examples and explicit local syntax coverage. Local pipelines are composed into new graphs, not matched to gallery specimens. Optional `/api/propose` transport accepts thought + named JSON data, and its untrusted typed proposal passes the same local compiler. Missing support and unrecognized clauses retain the previous specimen with a distinct diagnostic. Separate data cannot silently be ignored in local syntax mode.
- A complete Build / Watch / Run / Create verified copy flow. Build and view actions never invoke `Q.execute`. Each Run records actual task outputs and exact source emission. Copy requires a run admitted for the current installed source, constructs from that existing emission, and records precisely one fresh child execution. It does not rerun its parent. Source and output verification precede displayed lineage advancement.
- Source-authored candidate bodies change the complete source while retaining identical task graph bytes. The previous runs remain available as explicit previous-source records. Phase, selection and view mode change neither source nor records. Import clears the active copy receipt and installs a still specimen without executing.
- Exact local parser clause → graph node → declared material territory inspection, including ordered operation ports, parameters and output types. Typed-plan imports use honest formal operation summaries. Every node remains accessible by keyboard even when the portrait is uncluttered. A single clause mapping to several nodes lists those nodes without suggesting a nonexistent dependency between them.
- Source, companion artifact, sampled-wave and RGB export/import. Both recovery buttons verify canonical identity without running the recovered task. Original words and typed provenance belong to the companion artifact; they are not claimed to reproduce automatically from the source genome.
- Current/missing/stale scalar states use actual source-matched records. Zero remains a valid recorded value. The numeric lens includes its fixed authored domain and unit; values outside that domain remain underflow/overflow rather than silently rescaling the source.
- Reduced motion begins still, mobile remains usable at 390px, and failed or stale proposal requests cannot overwrite an edited draft. Proposal cancellation and newer builds/imports/candidates abort or invalidate pending requests. The browser stores no provider credentials.

## Renderer and generated anatomy

`LifeformRenderer.compile(graph, design)`, `draw(canvas, compiled, phase, options)` and `pick(projection, x, y)` have no runtime execution capability. They use the approved Anatomy material/pose API, the committed categorical owners, actual graph edges and shared operation anchors. Material, crests and graph anchors move together.

Owner palettes delegate to the shared `Chroma.colorFor` contract. Strength zero and omitted chroma use authored neutral ink; strength one uses role pigment. Recorded scalar views apply authored strength exactly once, preserving missing/stale status colors and desaturating unbound regions. Palette composition is pure and tested without interpreter execution.

The renderer uses 6,000 tissue samples for the focused view, normalized circular soft kernels, source role colors, four structural crest tracks (1,204 vertices), twelve shared depth buckets and reused Anatomy sample buffers. Neighboring crest segments with identical depth/owner are joined before Canvas submission. Inspection highlights declared owner material; picking selects an actual sampled owner. Bounds are fixed over the gesture rather than refitting the camera on each frame.

Root reassigned `anatomy.js`'s generator to this workstream for the final visual pass. Its validators, material charts, transforms and sampler were preserved. The generator now derives continuous primary proportions from dependency depth, arithmetic/selection/effect/sequence operation counts, and merge/fanout degree. Ordered dependencies produce asymmetric subordinate branches. Longer serial graphs can produce a secondary chamber on an attached neck; guarded-effect graphs can extend a wake. Seed variation controls bounded eccentricity, handedness, curvature and unequal appendage lengths. There is no family-name lookup in generation or rendering. Every operation has positive primary material territory; ornaments repeat existing owners without inventing computations.

The contact sheet shows six different actual generated task bodies, including a serial subordinate chamber, transverse guarded routing form, asymmetric filter sweep and elongated arithmetic form. This is a bounded chamber/spine grammar with varied assemblies, not a claim to unrestricted anatomy or a measured human beauty score. Smooth joined/watertight surfaces and global nonintersection are not established by root/socket coincidence.

## Verification

`verify-creation.py` uses independent expected outputs and an instrumented interpreter. The browser suite passes 47 checks covering zero executions during build/view/import/recovery, actual FIFO grants 4 and 5 from a 9 L pool, squared sum 38, three verified generations, both recovery codecs, source-changing candidates, stale records, malformed imports, exact clause/material links, recorded zero, proposal validation, delayed-response rejection, mobile and keyboard use. There are no browser page errors.

`node verify-anatomy.cjs` passes 28,489 numeric/ownership/chart/resource checks after the generator change. All ten library DAGs with three distinct seeds each validate as generated assemblies and encode under the full canonical source ceiling; the largest observed source is 12,765 bytes. This verifies those thirty cases, not all possible graph sizes.

The latest documented local headless Chromium run uses 20 warm-up frames and 300 measured frames at a 1,100×1,000 backing canvas, DPR 1: median 13.7 ms, p95 17.0 ms, maximum 18.9 ms. These timings cover synchronous geometry and Canvas submission on this Linux workstation, exclude final compositor presentation and requestAnimationFrame scheduling, and are not a physical mobile measurement. `creation-verification.json` contains the exact environment and check list.

## Explicit limits

Static hosting offers the documented bounded syntax and typed-plan import. Arbitrary English needs the separately running proposal service; local type/guard validation cannot prove agreement with every English sentence. Generated bodies use chambers and curved capped spines; fins, membranes with independent topology, loops and arbitrary external capabilities are not implemented here. Runs and copies are individually bounded and explicitly requested, with no invented per-session copy cap. Three generations is a verification case, not a runtime maximum.
