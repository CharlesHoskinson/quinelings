# Experimental generated assembly implementation

`anatomy.js` is a dependency-free CommonJS/browser module. Source grammar identity is `qdl-assembly-experimental`; this is not a QDL version freeze. `design/anatomy.schema.json` describes its closed syntax. Runtime adds ordered parent-tree checks, complete positive-width ownership partitions, graph coverage, hinge-path bounds, and finite numeric admission.

The first grammar includes bowed axial spines and positive-axis chambers. Spines use `C(u)=(bx L sin(pi u), L u, bz L sin(pi u))`, linear positive radii, an azimuthal side chart and explicit planar disk caps. Fixed transverse circles and strictly increasing axial y avoid frame-transport singularities. Chambers use two regular stereographic hemisphere disk charts; the convenience material sampler uses normalized height/longitude and analytic ellipsoid-gradient normals, including poles. Caps meet sides positionally; smooth cap tangents and smooth inter-component unions are not claimed. Chart inputs outside the unit disk reject exactly, without a floating tolerance enlarging their domain.

Every generated organism has a dominant chamber. Actual fork/convergence relationships select bounded subordinate branches; serial graphs receive axial continuations. Lower tails repeat an existing owner. At most four attachments leave a parent; at most sixteen parts and depth four are accepted. The full generated expression is authored source. Rendering never reconstructs anatomy from a seed alone.

Owners are complete, nonoverlapping longitudinal strips. Internal boundaries belong to the upper strip, and the final endpoint to the final strip. Every real graph node owns positive territory; compilation maps IDs to exactly the caller's node ordering. Frame allocation reserves an interior point in every territory and a point in every disk chart, then distributes the remaining global budget by estimated rest area. Therefore the accepted 4,000-point minimum covers even sixteen parts and sixty-four operations. No chart has an infeasible hidden 128-point floor.

Four-tick gestures use fixed gather/unfurl/glide/hover templates with quintic interpolation. Every child origin is computed from the actual parent surface socket; tissue, normals, anchors and crests share the same nested affine maps. The root uses one positive diagonal scale and bounded rotation. Phase requests outside ±1e9 radians fail closed. Geometry contains no interpreter, random clock, task trace, or execution side effects. The generator alone uses deterministic seeded arithmetic. Compilation snapshots and freezes authored source; later edits cannot stale its cached pose/material plans.

The API is:

- `validate(anatomy)`, `validateOwners(anatomy, graphOrNodes)`, `validateGesture(gesture)`.
- `generate(graph, seed) -> {anatomy, gesture}` consumes an ordered DAG; it does not validate kernel types or effects.
- `compile(anatomy, nodeIDsOrNodes, gesture)` snapshots geometry and owner ordering.
- `pose(compiled, phase)`, `sample(compiled, componentID, u, v, phase, chart='side')`, `sampleChart(compiled, componentID, chart, diskA, diskB, phase)`, `anchor(compiled, nodeID, phase)`, and `socket(compiled, childID, phase)` are passive.
- `frame(compiled, phase, {budget, crests, reuse?})` returns `Float32Array` points with stride four `(x,y,z,alpha)`, normals with stride three, `Uint16Array` owner indices, and ridge point lists. Tissue budget is 4,000–24,000 globally. Two to four 301-point crests use at most 1,204 vertices, below the legacy 1,806 cap. Optical alpha is a baseline for renderer normalization. With `reuse:true`, typed point/normal/owner buffers are overwritten by the next reusable frame of that compiled body; default calls return independent buffers. Rest samples and owner indices are cached, and the point loop uses direct affine arithmetic without per-vertex object allocation.
- `portraitFrame(compiled)` returns fixed conservative unprojected bounds `{cx,cy,cz,width,height,depth}` using the actual template maxima and cumulative joint reach. Projection/viewport fitting belongs to the renderer.

`verify-anatomy.cjs` passes 23,649 checks over serial, fork and merge DAGs, two extreme seeds, arbitrary phase seeks, source mutation after compilation, child sockets, azimuth/equator/cap seams, owner/anchor consistency, minimum and maximum budgets, malformed records, depth/fanout/hinge paths, all gesture stage boundaries and 16-part/64-owner bodies. These are numeric implementation checks, not a proof of global embedding or visual quality. The browser renderer owns complete silhouette/film/performance inspection; its first screenshot prompted the dominant-chamber and tighter-framing refinements described above.

`spec/lean/QDL/Assembly.lean` kernel-checks the actual quintic polynomial correspondence, bounds, first and second derivatives, endpoints, interval preservation, positive accepted spine length/radii and chamber axes, monotone axial y, positive taper, exponential scale product, shared affine attachment origin, half-open owner interval disjointness and boundary ownership, reserved sample budget, and the 1,204-crest/25,204-total aggregate bounds. Its `Gesture`, `SpineControls`, and `ChamberControls` records deliberately model local contracts rather than claim the complete JSON grammar.

`scripts/check-assembly-domains.cjs` checks 36 numeric schema endpoints against exact Lean declarations, three tag correspondences, and 22 runtime rejection cases; it lists structural constants and explicit pending obligations. Lean is checked with `lake env lean QDL/Assembly.lean`. No new axioms or admitted proofs were added.

Still unproved: complete grammar/parser/IEEE-754 correspondence; parent-tree induction and total partition coverage; atlas rank/transition derivative proof; piecewise C2 gluing across the gesture score; global nonintersection; C1 watertight unions; conservative-frame formal proof; and beauty. Positive scalar radii and determinant arithmetic do not discharge those obligations. Quint should model lifecycle/source-bound run transitions and bounded structural judgments; Lean should continue the exact mathematical chart/motion/ownership contracts. Neither substitutes for complete-body visual acceptance.
