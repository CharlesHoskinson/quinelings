# Chroma formal integration

The material-territory and optional scalar-lens declaration is part of complete QDL source identity. The formal integration retains the existing organ, membrane, rhythm, constructor, source-admission, and operational proofs while extending the typed syntax with every new authored field.

## Typed syntax and correspondence

`Design.lean` represents optional chroma with a model, palette, bounded strength, and optional scalar lens. The lens retains identifier, label, unit, lower/upper endpoints, optional threshold, and all node/path bindings. Distinct key/index constructors preserve path syntax. Validity includes string lengths, forbidden prototype keys, bounded indices/path length/binding count, unique bound nodes, strictly ordered domain endpoints, and an inclusive threshold.

There is no new global magnitude cap on scalar domains. Rational authored values model the domain relation, while JavaScript remains responsible for finite inputs and finite differences. The schema checker now traverses nested arrays and alternatives and accounts explicitly for relational endpoints/thresholds. It checks 42 numeric controls as well as the new string and collection limits.

Fixtures use `forProgram(item)` and the runtime binding validator, including Lanternkeeper's actual `faultScore` domain `[0,1]` and threshold `0.625`. An additional fixture preserves omission of both chroma and rhythm. The concurrent Lean work adds graph-membership consequences and a generated Lanternkeeper membership theorem; those additions were preserved.

## Evidence and view semantics

`Chroma.lean` proves that a displayed scalar requires a current complete-source identity, success, and an exact declared binding. Stale-source, failed, unbound, and unavailable numeric evidence cannot supply a scalar. Numeric zero remains a value. Clamped normalization stays in `[0,1]`, is monotone on a valid domain, and maps its endpoints to zero and one. Switching the view mode preserves runtime and evidence; newly authored source begins with no cached trace.

The separate concurrent `ChromaSemantics.lean` builds on these definitions for explicit missing/stale/invalid/underflow/valid/overflow statuses and bounded rational linear-light mixing. The existing generic complete-source quine/admission proofs automatically cover full chroma metadata; no new fields are dropped from source.

Quint now includes chroma/lens identity tokens, sampled domain/threshold relations, cached trace provenance, and value-view selection. Its safety condition permits scalar display only with a matching source and full design profile, successful numeric evidence, and an authored lens. Negative controls detect stale display and chroma mutation during rendering. Changed color strength or lens metadata prevents child admission. View changes preserve execution and effects.

## Trust boundary

These are conditional models, not proofs of JavaScript trace creation, path resolution, canonical serialization, source matching, browser cache invalidation, IEEE-754 interpolation, displayed pixels, or visual quality. Trace provenance and numeric availability are supplied inputs. Quint explores finite tokens and numeric samples, not every possible source or color. Lean's audit checks theorem dependencies without project axioms or admitted placeholders; JavaScript and browser checks cover the implementation boundaries.

Primary project references: [Lean documentation](https://lean-lang.org/documentation/), [Quint documentation](https://quint.sh/docs/). No external mathematical result is needed beyond the ordered-field and source-equality proofs checked in the repository.
