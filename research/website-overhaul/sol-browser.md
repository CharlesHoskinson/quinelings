# Browser audit and measurable laboratory proposal

Measured October 4, 2026 in headless Chromium using actual pages on an ephemeral localhost HTTP server, 1440×1000 viewport. No deployment or program/runtime changes. Reproducible harness: `sol-browser-measure.cjs`; raw observations: `sol-browser-measurements.json`; screenshots: `sol-v1.png`, `sol-gallery.png`, `sol-create.png`, `sol-ranch.png`. Browser emitted no page errors.

## What the controls actually do

**V1 workspace (`v1.html`).** Ten recipe buttons admit source artifacts. Task declaration and intent editor are authoring controls: Build changes source; inputs are run observations. Run creates a result record; reproduction evaluates a fresh instance; verification/recovery are separate source operations. Selecting graph nodes explains anatomy ownership and exposes recorded node values. Phase is a manual gesture scrubber. There is no autoplay control and `v1Workspace.paused` always returns true.

Water-total default Run produced `{liters:4,measurements:3}`. Replacing readings with `[8,2]` and running produced `{liters:10,measurements:2}`. Source hash remained `ql_e02a5c069ddc078b3086c9b3a07918030bc3c90e1bad9bbbb41f1f351ad572b1`; input hash changed. All 16,000 entries in the 4,000-point geometry buffer were identical (RMS difference 0, maximum 0). Owner arrays and rendered canvas PNG bytes were identical. This is a successful task change with zero body change, not a living response to observations. Do not claim these controls morph its anatomy.

One second idle preserved phase and canvas PNG exactly. Scrubbing phase to 25% changed 11,996 geometry entries, RMS .0033822823, maximum .0119180083 in renderer coordinate units, without changing source. The fourth entry per point is included in this aggregate; XYZ-only RMS would be clearer in a user lab. Selected `readings` exposed ownership `trunk u 0–.25; tail u 0–1`. Node highlighting is a view overlay on owned tissue; the ownership does not prove task execution or cognitive state. Portrait colors are calculated from design and node index, without recorded result passed to the color call.

**Legacy gallery (`index.html`).** The scenario selector explicitly encodes overridden literal values in source; task-cycle and committed rhythm controls also rebuild its program. This differs materially from v1 observational inputs. In Lanternkeeper, default confirmed fault score .875 produced `maintenanceNeeded:true` and simulated repair receipt. Healthy scenario score .125 produced false and skipped receipt. At identical paused phase .3039696, source and canvas pixels changed. Operation count and all operation frequency labels were unchanged: literal organs frequency 11, weighted mean 16, compare 22, evidence 34, get 24, choose 23, reports 28, action 27. Pixel change therefore does not establish changed graph topology or changed frequency. Keep a separate topology/constant/design/record comparison.

Gallery starts with motion enabled; the harness paused it before fixed-phase comparison. Role/opcode colors identify instruction classes; the recorded-value scalar lens is a different explanatory view, with an explicit threshold/domain and result record. Exact RGB genome encoding is a third thing entirely: underlying byte records are recoverable data, not a screenshot of colored organs.

**Create (`create.html`).** Initial authoring text is `allocate 9 L to [{"id":"fern","amount":4},{"id":"sage","amount":7}]`. It builds three operations and a four-part body before any task result exists. Explicit Build remained READY / NO RESULT YET. Run granted 4 and 5, remaining 0. Controls include example task strings, constrained authoring/data inputs, optional external interpretation service, body candidate choices, Body/Program/Recorded result modes, manual phase, explicit Watch gesture, node/clause inspection, trace replay, source/genome export/recovery. Building a constrained textual task is not evidence that arbitrary prose, an LLM's internal thought, or a City agent is translated automatically. Recorded results should be labeled observations of this finite local program.

**Ranch (`ranch.html`).** Boots with ten residents and zero social ticks, “A QUIET GARDEN / GESTURES OFF · SOCIAL TIME OFF.” Canvas PNG remained identical across one second idle. Gesture and social time are independent toggles; advance/step, demo family construction, parent/recipe/seam preview and admit controls are separate explicit local actions. Selected-node inspector explains owned tissue and actual input edges. Source contains authored anatomy/ownership, while resident placement/social simulation is session state. Body/merge/mate recipes need their own source and lineage comparison; changing parents or previewing is not execution or admission. Do not advertise automatic idle breeding or persistent live City action.

## Concrete interactive lab

Put three explicit experiments beside two fixed-phase canvases, supported by actual runtime measurements:

1. **Change observations.** V1 water-total readings `[1,2,1]` versus `[8,2]`: outputs 4→10, source unchanged, geometry RMS 0, ownership unchanged. Display selected node's exact runtime value and record/input hashes, and explain why the same program can calculate a different answer with the same body.
2. **Change source.** Build a deliberate constant, operation, anatomy, or gesture edit. Hold phase/camera/sample budget fixed. Show source hashes, node/edge counts, ownership/component changes, changed-point percentage, XYZ displacement RMS/max, and exact source-emission equality. A legacy scenario can demonstrate encoded constants, clearly labeled as a source edit.
3. **Change view.** Phase 0→25%, node selection, or a supported role/value color lens. Display source equality, task evaluation count, point displacement, and owner/color changes independently. Gesture scrubbing should show different poses with zero new task evaluations.

Use actual point buffers (same indices and 4,000 sample budget), XYZ distance per point, owner-array equality, operation/edge set diffs, design diff, and source byte equality. Compute `rms=sqrt(sum(dx²+dy²+dz²)/pointCount)` and max Euclidean displacement; distinguish a genuinely comparable same-topology measurement from a different-topology comparison. Canvas pixel difference is secondary and should be fixed camera/phase/resolution and exclude highlights. Include sample count and units. Never substitute an animated UI badge for a measured runtime change.

Make “Play gesture” an explicit reversible view action, default paused, honoring reduced motion. A task run is an event, not continuous cognition. Show source/record/value/pose as separate quantities with clear labels. Support selected-node lookup from runtime occurrence trace, using the trace's actual schema rather than inferred inputs or recomputing a made-up intermediate value. A records timeline can show execution/reproduction/recovery operations and zero evaluations for passive view changes.

## Defensible explanation and novelty

The demonstrated mechanism combines a finite typed task graph, deterministic local execution, a self-emitting exact canonical-source wrapper, source-owned anatomy, authored gesture equations, and independently decodable harmonic/RGB data. Explain each with its own visible proof. The worthwhile website novelty is a single inspectable object joining computation, anatomy ownership and recoverable identity, with independently testable controls. These measurements do not establish a novel quine technique, autonomous intelligence, biological life, universal prose compilation, or task-driven anatomy in v1. A rigorous experiment that visibly reports a zero is more persuasive than implying every input moves the body.
