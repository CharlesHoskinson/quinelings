# Material territories and recorded scalar lenses

Implemented in `chroma.js`, checked by `node verify-chroma.cjs`. The module is a pure rendering projection. It has no interpreter dependency, clock, random state, effects, or execution entry point.

The fixed `roles-1` palette has six body roles: input (cyan), process (blue), judgment/evidence (amber), action (coral), quotation/reconstruction (violet), and report (green). Every current kernel and legacy operation has an explicit mapping. These six colors do not replace exact opcode colors or RGB genome bytes. Process includes arithmetic, transforms, scheduling, and retries; the exact graph legend retains those distinctions.

Material ownership uses only source graph depth, stable node IDs, family topology, and membrane coordinates `(u,v,k,total)`. Nodes at each depth form a longitudinal band; canonical ID order assigns peer lanes. Each node has unit territory weight; an explicitly scalar-bound node has weight two as a presentation focus. This emphasis does not assert greater graph importance or a larger numeric value. Band widths and lane widths follow these weights. Closed bodies offset the first band's center to the longitudinal seam, so both sides share ownership. Categorical boundaries remain intentionally crisp. Screen overlap creates no adjacency and motion never reassigns pigment.

An ownership field compiles in `O(V log V)` time and `O(V)` memory. Owner lookup scans bounded depth/peer lists. The renderer can cache its bounded sample owners once and reuse them at every phase. Compilation caches by shape and a source-derived signature; ownership changes when nodes, levels, family, or authored lens bindings change. The field does not infer an exact geometric attachment between organs and membranes.

`resolveLens(design,taskRecord,status)` reads a single recorded task cycle, supplied by the caller after exact source/run matching. It never executes. Each binding reads an ordered own-property path from the matching trace row's `value`. Only finite JavaScript numbers count. Missing records/rows are `not-evaluated`; absent paths, nonnumeric values and duplicate node trace rows are `invalid`. Explicit caller status `stale` hides prior-source values. Valid values retain their exact number; `underflow` and `overflow` retain it while clamping only color normalization to the fixed declared domain. Source/run/task-cycle attribution and invalidation remain caller responsibilities.

The quantitative scale is a fixed low-violet to high-pale-yellow sequence. Intermediate display colors use bounded linear-sRGB interpolation. Role and scalar colors blend toward the authored neutral according to strength; absent chroma and zero strength preserve neutral. Scalar-unbound territories are moderately desaturated, retaining their relative linear luminance. The root renderer retains geometric density/depth opacity, adds a narrow pearl crest, and displays exact-value labels, domain, unit, threshold and nonnumeric-state hatching. Hatching and text are necessary because under/overflow share endpoint colors and state colors are not sufficient identifiers.

Color is a lossy projection. Node territories do not encode dependency port order, and scalar values are not inferred from opcode, literal size, motion phase, or display history. The graph and exact byte genome remain authoritative. No provenance mixtures, reaction–diffusion, causal contribution, or hue cycling are included in this version.

The design choice to keep shape opacity independent from semantic chroma follows the separate material/lightness controls described in [CSS Color 4](https://www.w3.org/TR/css-color-4/); this implementation uses explicit sRGB colors and linear-RGB interpolation rather than claiming physical pigment, photometry, or perceptual uniformity.
