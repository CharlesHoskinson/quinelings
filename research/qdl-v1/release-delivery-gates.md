## Remaining stable-release blockers

1. **Freeze the normative QDL 1 contract explicitly.** Record reviewed pin, supported runtime/profile scope, signature/error/bound vectors and fixture identities as the stable contract. Current candidate labels and manifest status are accurate. The already passing `--check` must remain the check, not a generator used to hide incompatibility.
2. **Retain an immutable matching artifact set.** Preserve the tested tarball above, source checkout, registry manifest and sidecar, golden canonical sources/full genomes, explicit migration pair and acceptance receipts under an immutable release/tag or equivalent retained versioned artifact. Document matching-runtime inspection, unsupported-pin refusal and explicit authored upgrades. `QDL-V1-UPGRADES.md` specifies this; actual stable retention remains pending. A mutable download path alone is insufficient.
3. **Complete package/status handoff against the retained bytes.** The package remains `0.0.0-experimental`; no npm publication is implied. If root changes packaging/version/build, record the new SHA256 and repeat installed-consumer checks for that exact archive. Reconcile current release statuses together: acceptance/publication/delivery correctly say candidate, but `execution.json` still has older “result-budget fix is underway”/“v1 acceptance remains pending” summaries beside completed delivery. Update current status without erasing historical report evidence, then publish claims no broader than the frozen scope.

No further semantic failure is established by this audit. Stable packaging/retention/status work is still real release work; completion of local tests is not permission to silently promote a candidate label. Conversely, live City actions, private chain-of-thought extraction, a durable shared host, full-JS proof, physical-GPU speed and arbitrary-English compilation are outside this release boundary and must not be invented as mandatory completion gates.
