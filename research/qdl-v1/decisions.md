# Root convergence decisions — candidate, not a released implementation

2026-10-04. All ten technical specialists and all five branding specialists have completed their reports. Branding copy is integrated locally and committed; technical implementation remains in progress. These decisions guide implementation; they are not acceptance evidence or a stable-release announcement.

1. Preserve legacy executable constructor bytes and semantics. Introduce a separately admitted, strict `qdl-program` version 1 payload inside the existing constructor AST. Both quotation copies carry the complete source-authored declarations, typed task, design, repeats, canonicalization and immutable registry identity. Do not add an inert JSON wrapper or reinterpret the legacy graph’s `version:1` as stable QDL.
2. Treat a thought as a bounded public declaration. Source carries observation, evidence, goal, decision, plan and task records with unique IDs and checked references. The compiler validates declared structure and references; it does not certify factual truth or extract private reasoning. Broader text interpretation remains a model proposal followed by validation.
3. Separate immutable typed constants from typed runtime input ports. Required bindings must be exact; optional values use explicit null. Supplied bindings never rewrite constructor source. Record a separate canonical binding digest. Symbolic normalized units describe quantities and do not implicitly convert measurements.
4. Keep the stable profile deterministic, finite and simulation-only. Evaluate the output-reachable DAG in deterministic authored-ready order; reject disconnected actions, action branch ancestors and effect-bearing guard cones at every admission path. No ambient network, clock, credentials, user JavaScript or real-world action is part of the language.
5. Retain the existing useful kernels under a closed pinned contract and add the seven proposed common primitives: input, arithmetic, compareValues, all, select, evidenceFresh and reconcile. Freeze signatures, parameters, types, units, empty/tie/error/overflow rules in a content-addressed registry. Preserve all existing operation colors/frequencies and append new roles without renumbering legacy entries.
6. Stage occurrence-local simulated receipts and outputs. A failed occurrence retains a bounded diagnostic and completed trace but publishes no occurrence-local effects; previous successful occurrences remain, and later occurrences stop. Stage serialization/schema/size checks before record or adapter-visible state commits. The verified oversized-MCP-response-after-commit bug is a release blocker. Target a 2 MiB complete semantic run cap; aggregate stores and transport envelopes require separate explicit budgets.
7. Expose the stable profile through an explicit SDK v1 entry point and shared closed adapter schemas. Keep existing Runtime callers and source identity compatible. Request replay must compare complete canonical payloads and never silently reopen used keys. A production interpreter may ship without durable host storage or real external dispatch; those capabilities must remain explicitly absent unless implemented and fault-tested.
8. Make ranch compatibility visible before construction. Revalidate offspring source pins, types, declarations, guard cones and output reachability. Construction, admission and explicit Run are separate events. Imported source ancestry remains a claim; retained construction evidence is distinct. Plan the ranch upgrades from the dedicated report, with persistence claims gated on passive restoration tests.
9. Use Lean for abstract structural and transaction lemmas and Quint for bounded lifecycle interleavings, with explicit JavaScript correspondence fixtures. Checked abstract theorems and sampled exploration do not prove complete JS refinement, GPU output or external exactly-once actions.
10. Quinelings / Living Thoughts is the fixed product identity. Apply the branding reports to present capabilities first; source-carried declaration, reusable input, durable-session and stable-v1 copy remains conditional until its corresponding implementation passes acceptance.

Implementation and release gates remain open. Conformance vectors, negative boundary fixtures, source/genome round trips, legacy golden identities, installed-package consumers, real MCP/A2A transports, Node 22 and current Node, browser flows and the final release audit must supply evidence before freezing the language.
