Living Thoughts.

A Quineling is a small program you can see. It follows explicit instructions, shows the result, and gives each step a place in an animated body.

Start with a thought: “Add these water readings.” Run the calculation, then find each step inside the creature.

A thought, made explicit.

A thought names a task you want to do. A program writes out the steps a computer follows. Here, one list of water readings feeds two calculations: add the readings, and count them. Their results meet in a report.

Readings of 1.5, 2 and 0.5 liters give a total of 4 liters and a count of three. Changing them to 2, 3 and 4 gives 9 liters. The instructions stay the same.

readings → add them → total  ┐
         → count them → count ┴→ report

The connections between these steps help choose the body’s mathematical construction. Every step is assigned a region you can select and inspect.

Input
A value you supply for a calculation. Here it is a list of water readings in liters.
Operation
One defined step, such as adding the numbers. Operations use values from earlier steps.
Interpreter
The software that carries out the instructions when you press Run.
Body
The visible mathematical form. Motion changes its pose; a recorded run supplies its value labels.

Make a copy.
A quine emits its own complete source. Each Quineling has a constructor that does this, so a new instance can be built from the source it produces.
The same source can be stored as wave coefficients or exact RGB values. These data records contain the complete program; a picture of the creature does not.
Recover three generations to build and run successive copies with the same inputs. Each copy is checked against the original source and result.
Source is the complete text needed to rebuild the program and its body. A constructor is the part that produces this text. Checking a copy of the source leaves the task unrun.

Write the steps.
Start with a task: “Find a route around the closed road.” Express it in QDL as typed operations and their connections. The interpreter reads the supplied observations, runs each operation when its inputs are ready, and records the result.
QDL makes the task explicit: what it observes, what it computes and what action it proposes. You can inspect the program and every recorded step.
Give the steps a body.
The source also describes an anatomy made from mathematical curves. Operations are assigned regions, colors group their roles, and connections show how values flow. The renderer animates this anatomy; the interpreter runs the task when you press Run.
