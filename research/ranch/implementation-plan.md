## Shared executable boundary

Use shared, closed-data modules for offspring construction and world transitions. The website must call the same controller semantics as the TypeScript SDK; do not create a canvas-only imitation of mating or births. Root integrates the Runtime and adapters, exact stores/transactions, source schema, mathematical sampling extensions and final verification. Three implementation workstreams can then own distinct files: pure offspring builder plus fixtures; pure world transition plus lifecycle fixtures; ranch scene and DOM experience. Subsequent documentation/formal work stays within the same three-worker scheduling limit.

A source-level builder consumes two detached artifacts and a strict construction request. It returns a complete validated source, companion when eligible, ordered origin rows, diagnostics and deterministic identities. It cannot access execution records or mutate session stores. The child is rebuilt for admission, not accepted from a preview blob. Body inheritance must preserve the complete task projection and its companion references; task recipes generate a new mechanical companion. The compile-time pure refinement evaluator remains available but interpreter/action calls are forbidden during construction.

A world transition consumes a detached authoritative snapshot and a closed command. It returns a fully preflighted next snapshot and small acknowledgement, or refuses before mutation. Admission has a separate pure staging transition. Shared geometry rules cover creation, import, birth, reservation and movement, including projected ink containment as a separate rendering premise. Do not rely on the old portrait fit as a screen-space collision bound.

## Existing SDK constraint that requires refactoring

Current Runtime.#admit materializes and then immediately inserts/enriches artifacts. It cannot safely be called midway through a ranch birth. Split it into a pure preparation path (canonical source, Q.describe/reconstruction, K/QDL checks, genomes, metadata conflict and count/aggregate-byte preflight) and an infallible commit path. Existing compile/recover/reproduce should continue through these same paths, preserving their public semantics. A ranch transaction stages artifact, derivation, receipt and world before committing any of them. A world-only rollback around the existing #admit is insufficient.

Only successful admissions enter the retained 128-receipt replay ledger. The key binds the entire canonical payload; matching retries return the original result before stale revisions/epochs are checked. World commands have their own bounded sequence receipt window. New-key retries of a consumed proposal must fail even if a prior admission used another request key.

## Browser/library reuse

Bundle a browser-compatible Runtime entry for the ranch, using the same TypeScript API and shared modules. Existing node crypto hashing needs a browser synchronous SHA256 compatibility path, checked independently against Node crypto, published vectors and browser WebCrypto. Random execution-record IDs remain separate from deterministic source/construction identities. The ranch render code consumes artifact snapshots and controller results; it cannot own admissions or task execution. Camera/view/pose clocks are separate from the explicit world tick controller.

The shared Anatomy sampler should expose bounded rest layout data using the existing plan machinery: local positions/normals, component index, operation owner, and component transforms. Existing frame limits remain unchanged. The scene performs a fixed maximum per-component pose update instead of recomputing every particle on CPU. Reserved chart/owner samples, conservative projection, glow cutoff and per-sample density weighting need explicit semantics and independent checks. Reduced motion and Canvas fallback settle into committed states without triggering transitions.
