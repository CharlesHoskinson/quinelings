# QDL v1 graphics assessment — specialist nine

The ranch has a sound reusable geometry foundation and a restrained garden composition. Its next graphics release should first remove repeated portrait work and enforce complete resource bounds, then strengthen source-derived silhouette differences, then make luminous material and inspection behave consistently across desktop, mobile and fallback. More particles would consume budget without addressing the visible weaknesses.

This is an assessment of the local production implementation, not a live-site audit or hardware benchmark. Read `AGENTS.md`, `docs/PROGRAM-CONTRACT.md`, `docs/QDL.md`, `ranch-renderer.js`, `ranch.js`, `lifeform-renderer.js`, `anatomy.js`, `chroma.js`, SDK frame construction, aesthetics/lifeform reports, and ranch verification evidence. Viewed existing desktop, dense, mobile and grayscale captures. Only this report and `graphics-fixtures.json` were written; no shared production edits, task execution, world actions, credentials, git operations or deployment.

## Top three bounded changes

### 1. Reuse the selected portrait and bound the whole graphics working set

Keep the existing single WebGL2 context, static rest VBOs and source-owned material IDs. They already avoid transforming every tissue point in JavaScript. Do not start by replacing them with an elaborate new GPU engine: current low submission time suggests measuring other costs first.

`ranch.js:render()` calls `renderer.detail()` on every scene redraw. Detail recompiles anatomy, asks the SDK for a fresh 4k array frame, creates per-point Canvas paths, and redraws the complete portrait even when the selected resident is one of the static residents after index seven. The SDK public frame deliberately returns copies; an internal renderer need not repeat that serialization path. Cache the selected compiled anatomy and reuse typed frame buffers, or share its existing compiled body. Resolve its phase explicitly and redraw only when selected source, phase, node, palette or raster dimensions change. Separate meadow submission, detail drawing, prewarm, compile/upload and whole-render timings. Reuse matrix/normal/palette arrays in `gpuBody`; its current fresh arrays per resident are avoidable.

Keep scene caps: 32 residents, ≤32k tissue samples, ≤8 animated bodies, ≤16 components/body and ≤2M meadow backing pixels. Add a hard aggregate ridge cap of 16,384 vertices (current maximum 32×4×128), a proposed 8 MiB accounted VBO cap, and a 16 MiB retained fallback pixel cap. Count layouts, crests and framebuffers separately. The VBO proposal has ample headroom over approximately 1.70 MiB for 32k interleaved tissue vertices plus maximum ridge vertices; it excludes JS compilation and framebuffer allocations. Prune unused body entries and dispose buffers/VAOs/programs explicitly. `Anatomy` already limits layouts to two per compiled body, but repeated compilation defeats this reuse. Bound queued sprite jobs by live body/pose keys and discard obsolete jobs after source/tier changes.

Cache keys: source hash + renderer revision + discrete layout tier; palette adds mode and source-matched record/cycle identity; sprites additionally include composition, raster resolution and actual pose bin. Palette changes must not retain every historical color. On context restoration, recreate one program, rebuild live buffers incrementally and remain paused. A failure after obtaining a WebGL context needs a separate/replaced fallback canvas; asking that same canvas for a 2D context may return null.

Acceptance: instrument ≥300 warm frames per documented backend/device at 10 and 32 residents, separately including compile/prewarm costs. Suggested physical-device release target: whole-render CPU p95 ≤8 ms and draw-start interval p95 ≤50 ms under the current 24 Hz scheduler; 41.7 ms is its ideal interval, so a 33.3 ms gate would require changing that scheduler. Record GPU duration asynchronously when supported and discard disjoint samples per the [Khronos timer-query specification](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/). Unsupported timing stays explicitly unknown. SwiftShader below the target should demote to a static meadow plus selected-body motion or stills, without blocking inspection. Across 100 source selections/tier changes/resizes/context recovery cycles, allocated bytes and job counts must return within caps; unchanged paused frames cause zero geometry rebuilds. These are proposed gates, not measured achievements. Explicit resource disposal and avoiding synchronous checks follow [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices).

### 2. Give graph-derived bodies stronger silhouette signatures and source-linked pigment

First use the existing chamber/spine vocabulary. Distinguish short serial programs through bounded opcode-class proportions: scheduling gains a broad low chamber and directional sweep; consensus/evidence gains a compact chamber and asymmetric crown; arithmetic retains the tall continuation. Fanout keeps a readable fork; convergence keeps unequal incoming attachments; long pipelines keep a neck and offset lobe. Preserve one primary mass and one subordinate feature, readable negative space and the current fixed gesture envelope. These are deliberate visual projections, not one appendage per job/vote/claim and not extra executable edges.

New generation rules change authored anatomy and therefore source identity. Apply them to newly created specimens and explicitly generated variants; do not silently rewrite existing genomes or freeze the current experimental assembly marker as a final v1 promise. Defer torus/moth/new mesh primitives until chamber/spine variants pass thumbnail recognition: importing the older ten-family gallery formulas into this assembly renderer would require real geometry, attachment and validation work.

Reserve 2–4 stable source-owned principal crests across the whole body, rather than picking the first four component indices. Current GPU ridges are four 64-segment sampled curves at most; detail/fallback instead use `Anatomy.frame`'s different 300-segment crest distribution and neutral mint strokes. Adopt a shared crest selector/material-domain representation and split segments at owner boundaries so interpolation cannot create an apparent third role. Crest selection must preserve the dominant trunk and attached feature without giving each small appendage equal light.

The current SDK frame supplies role colors without a lens state, and ranch records are only shown as text. Wire an explicit view palette through meadow, detail, fallback and candidate rendering using existing `Chroma.resolveLens` and `colorFor`. Validate the selected record's canonical source and task occurrence before resolving it; no record means not evaluated. Use the authored fixed domain and exact numeric path, with text/symbols for underflow, overflow, stale and invalid. No automatic min/max rescaling or fabricated zero. Cache palettes outside the point loop. Role colors remain shared; species identity comes from shape. Display RGB byte genome and exact opcode identity remain independent of lit, antialiased body color.

Acceptance: twelve phases, all ten founders plus fork/merge/deep/64-node fixtures; every rendered owner exists in source, every operation retains a reserved sample at all tiers, seams/socket roots remain coincident and no source changes under view controls. Review grayscale and role-color contact sheets at 64/96/160 CSS px. Proposed human gate: two reviewers match at least 8/10 unlabeled founders after a labeled reference; record confusion pairs rather than declaring a shape metric proves beauty. Lens fixtures must cover zero, valid midpoint, bounds, overflow, absent path, invalid type and mismatched source with identical ownership/source before and after. Retain current measured LOD tolerances initially and extend to all fixtures/phases; do not replace them with an unproven 5% claim.

### 3. Make luminous motion and mobile/fallback inspection agree

Use the same bounded affine gesture and stable material ownership in every backend. Keep 2–4 colored crest cores, a narrow pearl highlight and a restrained underlight only on selected principal curves. Never add a particle emitter, full-screen bloom or continuously animated decorative substrate. Current GPU tissue is soft round points with low-opacity lighting, so replacing square dust is already obsolete advice for this meadow. Improve depth coherence instead: all GPU vertices currently have clip depth zero and ridges draw after tissue; detail likewise draws all ridges last. Try bounded shared depth buckets for tissue/ridge segments on the selected portrait first, and measure before sorting the complete meadow every frame. Ordinary depth writes cannot solve translucent overlap.

Normals are posed in model coordinates while camera projection rotates geometry; use the same coordinate frame for light/view directions when introducing a rim term. Keep any light multiplier bounded and preserve role hue. Shared tissue quadrature weights are normalized, but caps, point footprints, overlaps and ridge exposure prevent exact raster invariance. Canvas fallback currently uses fixed per-point alpha and neutral crests, so it needs separate equal-exposure calibration. Do not infer that CPU/GPU images are already equivalent.

Six pose bins over the 12-second cycle give approximately two seconds per pose: acceptable as explicitly labeled cached poses, weak as continuous living motion. Default fallback to a canonical still with selected-pose stepping; optionally test more bins for one selected resident within the same byte cap. Six-bin bounds should remain as a compatibility mode until actual motion review establishes improvement. Reduced motion removes deformation and ceremony transitions while preserving committed admission text and a complete still. Painting, selection, seeking and context restoration must never run tasks or advance social time.

On mobile, treat the whole garden as an overview. Present the selected creature at ≥160 CSS px when space allows, with resident paging/list navigation and nearby source-owner controls. Keep all residents reachable even if only four have enlarged thumbnails. Add a ≥44 CSS px project target for DOM controls; WCAG 2.2 AA's minimum is 24×24 CSS px with specified exceptions, so 44 is a usability proposal rather than its AA requirement. See [W3C target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Convert pointer tolerance from CSS pixels consistently; current portrait picking uses a fixed 28 backing-pixel radius, which is only about 10 CSS px at 130/360 scale. Resolve overlapping meadow bounds in displayed order and expose the exact DOM node list rather than claiming anchor-nearest picking is exact tissue selection. Only draw/prewarm visible habitats using an intersection gate in addition to the existing hidden-document pause.

Acceptance: 320/390/768/1440 CSS px, DPR 1/2, both backends, keyboard-only and reduced motion. No horizontal overflow, all resident/node controls reachable, clear selection outline plus owner/value text, and meaningful canonical still. Compare same source/phase/palette images and full 12-second gesture films; principal openings and attachment roots remain visible, no camera pumping, no bright far crest mistaken for a near feature. On paired fallback/GPU optical fixtures target ≤20% integrated luminance and ≤25% silhouette-area drift initially, then tighten from measured artwork. Test context-creation failure, post-creation shader failure and restoration. Spy on interpreter/world dispatch: rendering and view actions produce zero calls, source/records/receipts remain unchanged. The fixtures contain these proposed checks, not browser results.

## Implementation boundary

QDL owns bounded anatomy, attachments, territory IDs, authored gesture and lens domain/bindings. Renderer policy owns sample tiers, backend, raster budget, primitive caches, depth approximation, pause/current phase, palette selection and inspection. A future crest declaration must be finite and validated, not arbitrary shader code. Preserve exact canonical reconstruction and both genome codecs in the CPU runtime; screenshots, GPU buffers and brighter motion do not establish source recovery, live biological behavior or hidden cognition.
