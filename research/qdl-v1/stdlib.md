# QDL v1 standard library candidate

Status: implementable review proposal, not an implemented registry. This document owns no runtime code. Read `AGENTS.md`, `docs/PROGRAM-CONTRACT.md`, `thought.js`, `kernels.js`, the ten existing program fixture envelopes, and `city-context.md`/`city-evidence.json`. Existing behavior was exercised in `/tmp/qdl-stdlib-probe.cjs` on 2026-10-04: all **53 existing fixtures**, five independently specified kernel cases and three negative/boundary cases passed. The isolated candidate reference `/tmp/qdl-stdlib-candidate-reference.cjs` also passes **18 independently specified candidate fixtures**, including a composed craft-bound recipe, in `stdlib-fixtures.json`. That reference covers reductions only, not complete validation, types, ports, codecs or production support. Proposed examples below remain acceptance oracles for the future production registry.

## Scope and evidence

The smallest useful release candidate is **24 retained legacy opcodes plus seven additions**, under a new registry/profile discriminator. Six additions are pure calculations; `input` is a pure invocation lookup. Retaining an opcode does not imply every legacy graph qualifies for stable admission. The existing `action` is a compatibility simulation receipt producer only. Actual world effects belong to a separate adapter; quine reproduction, rendering, replay and source recovery cannot dispatch them.

City evidence supports task vocabulary and constraints, not a captured live thought or current recipe/price. The actual capture timestamps are about **12:55 UTC**, despite the approximate 06:55 UTC in the context note. Public [First Night](https://midnight.city/docs/connect-to-midnight-city/first-night/) describes bounded missions grounded in observed state. [Gathering](https://midnight.city/docs/gameplay/gathering-and-resources/) requires availability, reservation and reachability; [crafting](https://midnight.city/docs/gameplay/crafting-and-workstations/) separates batch commits and pending results; [economy/needs](https://midnight.city/docs/gameplay/economy-and-needs/) supplies inventory, offer and owner-limit guards. The static-code capture distinguishes reported progress from confirmed results. These motivate the recipes below; invented examples are explicitly synthetic. The local captured text was read, so no further scraping or connection was necessary.

Do not add mission, gather, craft, eat, merchant, checkpoint, or transfer opcodes. Compile these as bounded recipes using the common registry. No expression strings, host callbacks, general-purpose map closures, timers, implicit clock, unit conversion, mutable storage or external RPC in v1.

## Types and uniform rules

Use source-carried types, rather than the current companion-only contract. `N[u]` means finite binary64 quantity in symbolic unit `u`; `Nat[u]` adds nonnegative safe-integer refinement (maximum 9,007,199,254,740,991); `B`, `S`, `Option<T>`, `Array<T>`, and closed `Record` follow existing IntentIR types. Status/kind fields have explicit finite enum refinements. All input bindings and every intermediate result must satisfy declared types/refinements. Array length <=512; DAG <=64 nodes; <=16 ordered ports per node; repetition 1–8; existing byte/depth budgets apply. An empty array needs a declared element type; never infer it as an arbitrary numeric array for a stable runtime port.

No coercion, implicit conversion, arbitrary object keys, missing-field truthiness or JSON `undefined`. Reject unsafe property names at every boundary. Exact equality is canonical JSON equality over equal types; `Option<T>` can compare with explicitly typed null. Ordering uses numbers of equal normalized units or strings, with JS UTF-16 lexicographic order, never locale collation. Normalize negative zero in canonical output. Units are symbolic equalities, not physical conversion or semantic proof that supplied values describe the world.

All arithmetic checks **every intermediate**, not just final output: finite-number overflow, zero division and safe-integer overflow fail with node/path/code. No saturation, wrapping or silent rounding into a different integer. Integer multiplication checks the safe result before division, even if a later quotient would fit. Fractional quantities use N; amounts, counts, revisions, attempt counts, timestamp ticks and recipe batch counts use Nat. Runtime checks are mandatory where compiler proofs depend on external bindings. Domain shortage is a finite result; malformed input and arithmetic overflow are structured execution failures with no fabricated output. Eager `choose` evaluates both producers; all branches must be safe. The library uses explicit defaults and `found` guards rather than a `choose` around an invalid `get`, empty extremum or divide-by-zero.

## Retained operations: precise stable signatures

The 24 names are exactly `literal,sum,mean,min,max,weightedMean,length,map,sort,dedupe,filter,compare,choose,get,clamp,budget,action,report,bfs,allocate,schedule,consensus,retry,evidence`. Preserve the experimental profile's bytes and observed behavior. For the new stable profile, apply the uniform validator and these explicit refinements:

| Operation | Signature / decisive semantics |
|---|---|
| literal | `[] -> T`, authored value and T embedded in source; immutable during invocation |
| sum | `Array<N[u]> -> N[u]`; left-to-right checked addition; empty 0 |
| mean,min,max | `NonemptyArray<N[u]> -> N[u]`; mean checked left-to-right sum / length; empty fails |
| weightedMean | `(NonemptyArray<N[u]>,NonemptyArray<N[one]>) -> N[u]`; equal lengths, nonnegative weights, positive total; check each product and sum |
| length | `Array<T> | S -> Nat[count]`; strings count UTF-16 code units, so emoji `😀` yields 2 |
| map | `Array<N[u]> -> Array<N[u]>` for multiply by dimensionless authored factor; square -> `Array<N[u*u]>`; no closures; empty [] |
| sort | `Array<T> -> Array<T>` with same-typed numeric/string own-path keys; stable ties retain input order; descending does not reverse ties |
| dedupe | `Array<T> -> Array<T>`; first canonical value/key wins; preserve order |
| filter | `Array<T> -> Array<T>`; authored same-typed comparison value and optional own-path key; empty [] |
| compare | `T -> B`; compare to authored same-typed constant; ordering restricted as above |
| choose | `(B,T,T) -> T` with optional/null unification only; eager, no control-flow/effect laziness |
| get | `Record -> T`; statically valid required own-property path; not safe optional lookup |
| clamp | `N[u] -> N[u]`; authored finite bounds share u and min<=max |
| budget | `(Nonnegative N[u],Nonnegative N[u]) -> {allocated:N[u],remaining:N[u]}`; allocate min, empty concept not applicable |
| report | `(T1,...,Tn) -> Record`; unique safe authored labels; 0–16 ports |
| allocate | `(Nat[u],Array<{id:S,amount:Nat[u]}>) -> {grants:Array<{id:S,requested:Nat[u],granted:Nat[u]}>,remaining:Nat[u]}`; unique IDs, FIFO, partial grants, empty leaves pool intact |
| bfs | `(adjacency,Array<S>) -> {found:B,path:Array<S>,distance:Option<Nat[edge]>}`; authored endpoints; FIFO ordered neighbors; blocked endpoint misses, unreachable `{false,[],null}`; start=goal yields singleton/0 unless blocked |
| schedule | `Array<{id:S,depends:Array<S>,duration:Nonnegative N[time]}> -> {order:Array<S>,jobs:Array<{id:S,start:N[time],end:N[time]}>,makespan:N[time]}`; unique IDs; first currently-ready row in input order; unlimited parallel earliest start; missing dependency/cycle fails; empty makespan 0 |
| consensus | `Array<{source:S,choice:S}> -> {choice:Option<S>,support:Nat[count],accepted:B,uniqueSources:Nat[count]}`; authored required positive Nat; first vote/source; tied support picks first-seen choice; empty null/0/false/0; agreement is not world confirmation |
| retry | `Array<Enum(retry,ok,unknown)> -> {status:Enum(completed,uncertain,exhausted),attempts:Nat[count],history:Array<S>}`; authored maxAttempts 1–8; unknown/ok stops; empty exhausted/0/[]; does not submit anything |
| evidence | `Array<{source:S,claim:S,value:B}> -> {state:Enum(unknown,supported,refuted,conflict),support:Nat[count],refute:Nat[count],sources:Nat[count]}`; stable decisions require authored single claim; first source+claim wins; empty unknown; legacy no-claim aggregate retained only in legacy profile |
| action | `(B,T) -> {status:Enum(simulated,skipped),action:S,payload:T}`; source `allowed` B and label; exactly one local receipt per successful node evaluation; never a world receipt; never feed simulated status into mission completion |

The stable `sum`/`map`/`mean` intermediate-overflow rule is stronger than today's direct `K.calculate`, which can return Infinity before `K.run` rejects the result. Keep these differences isolated by registry identity. `schedule` has no workstation/resource contention model; a recipe serializes mutually exclusive jobs by explicit dependency edges. `bfs` is unweighted; choose only shortest edge count, not claimed travel time. Freeze the existing leaf-node rule (absent adjacency entry has no neighbors); freshness/authoritativeness is checked on the supplied graph envelope.

## Seven additions: complete smallest registry delta

Names below are proposed identifiers. Each has a closed parameter schema and fixed semantics; rename together at registry freeze, never infer names from natural language.

| Name | Ports / params | Result and refinement |
|---|---|---|
| input | 0 ports; `{name:S,type:T}` | Required invocation binding of T; no source default/value; missing/extra binding fails before execution |
| arithmetic | 2 ports `(N[u],N[v])`; `{kind:add|sub|mul|div|floorDiv|min|max}` | add/sub/min/max require u=v and return N[u]; mul returns N[u*v]; div returns N[u/v], denominator nonzero; floorDiv accepts Nat[u], positive Nat[v], returns Nat[u/v]; Nat-only add/mul/min/max preserve Nat; Nat sub requires left>=right; real results stay N |
| compareValues | 2 equal-typed ports; `{operator:eq|ne|gt|gte|lt|lte}` | B; same equality/order policy as compare; dynamic observation thresholds no longer authored constants |
| all | 0–16 B ports; `{}` | B, conjunction; zero ports true; mission recipe must explicitly reject zero checkpoints rather than depend on vacuous truth |
| select | `(Array<T>,Record<Q>)`; `{keys:Array<S>,order:Array<{path:S,descending:B}>,default:T}` | `{found:B,value:T,index:Option<Nat[count]>}`; Q exactly declares the unique top-level field names in keys and their same-typed values. Query keys are required fields, not dotted paths. Keep rows matching every query field by canonical equality; then stable lexicographic order. Empty order preserves input order. First eligible wins; no match returns authored default and index null. Path list entries unique; order keys numeric/string, no optional keys. Default schema equals row schema. No mutation |
| evidenceFresh | `(Array<E>,S,Clock)`; `{allowedKinds:Array<Enum(observation,testimony,inference)>}` | Evidence assessment described below; explicit policy determines admitted kinds |
| reconcile | `(S,Array<R>,Policy)`; `{}` | Receipt assessment described below; never performs retry or world action |

`select` replaces a separate find, first, sortMany, optional-get and inventory-lookup addition. Its result always contains a typed usable default, but `found=false` must guard any proposed action. Default values are source policy, never observations or completion evidence. Example inventory default `{id:"",amount:0}` makes a missing item safe to inspect. Empty query/keys means all rows eligible. To choose food, supplied candidate rows include observed restoration and readiness facts; query `edible=true`, order restoration descending then id ascending. The authored restoration policy decides whether greatest restoration is appropriate; do not bake it into language semantics.

`evidenceFresh` E is the exact record `{id:S,source:S,claim:S,value:Option<B>,kind:Enum,observedAt:Nat[tick],revision:Nat[revision]}`. Clock is `{now:Nat[tick],maxAge:Nat[tick],minRevision:Nat[revision]}`. IDs unique, source nonempty. Accept only matching claim, allowed kind, non-null value, `observedAt<=now`, `now-observedAt<=maxAge`, revision>=minRevision. Equal age/revision thresholds count as fresh. A future timestamp is skipped, not clamped. Preserve complete original records in ordered `used` and `{record,reason}` `skipped`; choose one skip reason in this order: claim, kind, unknown, future, stale, revision. No implicit trust in source labels. No implicit time or transport verification.

Reduce eligible records per source and requested claim: identical repeated booleans count once; a source supplying both true and false is listed once in `sourceConflicts` and contributes once to each polarity. Do not silently overwrite, pick first, or pick latest. support/refute count distinct sources in each polarity, sources counts their union (so support+refute can exceed sources). `sourceConflicts` follows first source appearance in `used`. state is conflict if both counts positive, supported if only support, refuted if only refute, otherwise unknown. Output exact `{state,support,refute,sources,sourceConflicts,used,skipped}`. Distinct source strings alone do not prove independence: the adapter should use stable provenance identities for copied testimony. Author can use old `evidence` where intentional first-report policy is sufficient; fresh mission confirmation uses the strict reducer with allowedKinds `["observation"]`.

`reconcile` R is `{id:S,operation:S,attempt:S,sequence:Nat[revision],status:Enum(confirmed,failed,pending,unknown),units:Nat[item]}`. Policy is `{requested:Nat[item],maxAttempts:Nat[count]}` with maxAttempts 1–8. Filter operation first. Exact repeated receipt IDs collapse to first occurrence; same ID with differing data fails `receipt-conflict`. For each attempt, increasing sequence gives successive observations (input order irrelevant; equal sequence with different data fails). Each attempt may terminate once: after confirmed or failed, identical terminal status/units is allowed, but changing terminal status/units or reverting to pending/unknown fails. Nonconfirmed units must be zero. Confirmed units>0; a zero-output operation needs a separate explicit boolean completion claim, not a fake unit commit. Count a confirmed attempt once, including when a terminal observation is repeated under another receipt ID. Checked sum confirmed units; checked attempt count; >maxAttempts fails rather than hiding overflow actions. Returned `attempts` is count of distinct attempts, **not** reads, retries requested or reproduction cycles.

Exact reconcile output `{state,confirmedUnits,confirmedAttempts,failedAttempts,pendingAttempts,unknownAttempts,attempts,mayRetry}`. Counts are Nat[count]. State precedence: any unknown -> unknown; else pending -> pending; else confirmedUnits>=requested -> completed; else attempts>=maxAttempts -> exhausted; else attempts=0 -> ready; otherwise retryable. mayRetry true only for ready/retryable. Zero requested plus empty receipts completes; any unresolved attempt still blocks. Confirmed partial units survive every other failure/unknown/pending. `confirmed` means adapter-supplied confirmation, never inference from action submission, saved plan, simulation receipt or requested quantity. This reducer is per operation over supplied complete attempt history; completeness/provenance remain adapter responsibilities. Retrying a failed batch requires the adapter's separate idempotency/authorization contract and a fresh attempt ID; `mayRetry` is advice, not permission.

## Finite recipes, not new domain opcodes

Recipes expand to ordinary visible DAG nodes. No hidden host algorithm. A builder fails with a structured expansion budget error if it exceeds 64 nodes; never truncates a recipe. The smallest initial recipe package is five builders with source-carried policy and exact fixture outputs:

1. **Checkpoint confirmation:** One bounded finish predicate per checkpoint; use fresh observation evidence restricted to its exact claim, then `compare(state,"supported")`. `all` combines 1–8 checkpoint predicates. Unknown/refuted/conflict means incomplete. The ledger remains in output; `all` alone loses reasons. Zero checkpoints is a recipe authoring error. Agent-reported done, static text and planned actions cannot satisfy a world-result checkpoint.
2. **Gather/trade/needs guard:** required booleans include found observation, fresh revision/age, available, owner allowance, capacity and route found. Read supplied reservation state, compare with permitted owner, then `all`. Output `{ready,reasons,proposal}` via report; recipe enumerates one reason per false guard in bounded authored order. Source has allowed=false/true only for local simulation. Offer prices/limits are runtime observations. Predicted proceeds via arithmetic multiply; spend preview via budget; settlement requires reconcile. Missing/expired offer yields ready=false, predicted quantity/proceeds zero and no simulated effect.
3. **Inventory and bounded craft quote:** `select(inventory,{id})` per authored material slot, default amount 0; selected inventory must have unique IDs (input refinement). For a fixed recipe with 1–4 materials and <=2 outputs, positive per-batch amounts, obtain each material bound via floorDiv(available,needed). Fold arithmetic min with requested batch count and free-capacity bound. Use Nat arithmetic for consumed quantity, outputs and predicted cost. Output requested/feasible/shortages; never confirmed=feasible. Compare skill, workstation type/family, locality and owner allowance as separate guards. Invalid recipe quantity=0 fails before execution; missing material returns feasibility 0. Capacity means a supplied additive unit budget with explicit per-batch net increase; v1 does not pretend to solve heterogeneous stack/slot packing. Net increase 0 omits the capacity divisor by source recipe construction. If fixed expansion exceeds 64 nodes, reduce the authored bound or decline that recipe; do not add callbacks.
4. **Route and schedule preview:** bfs on a fresh supplied adjacency snapshot and closures; blocked start/goal returns no proposal. Equal edge paths follow neighbor order. schedule computes dependency times; shared workstation jobs must explicitly depend on the preceding job. No path-weight promise, implicit terrain or current wall time. Scheduling is prediction, not confirmation or reservation.
5. **Outcome reconciliation:** reconcile exact complete receipts; unknown/pending means observe again, never submit again. Three confirmed units plus a failed fourth stay three confirmed units. Fresh input history changes run output while source stays identical. Legacy retry is useful for abstract predeclared local attempts; keep it distinct from this world-receipt recipe.

Recipe units must also compose: requested/feasible batches are `Nat[batch]`, available material is `Nat[item]`, per-batch material is `Nat[item*batch^-1]`, free capacity is `Nat[space]`, and net increase is `Nat[space*batch^-1]`. Thus floorDiv returns `Nat[batch]` and consumed material multiplication returns `Nat[item]`; the numeric examples omit these annotations for readability. Distinct material item IDs are runtime provenance/schema labels, not implicitly convertible inventory units. The fixture harness tests numeric reductions only; typed registry acceptance must separately check this unit algebra.

For recipe 2, freshness can be computed with compareValues/arithmetic, using `min(now,observedAt)` before subtraction and a separate observedAt<=now guard so Nat subtraction is always safe. Material/cost recipes use explicit found flags to distinguish missing observation from genuine observed zero. A 4-material quote can fit: four select/get/floorDiv triples (12 nodes), four amount guards, five min folds, a handful of input/literal/output nodes; full reason ledgers and all workstation predicates may exceed the limit and require a smaller declared recipe. Node budget is checked on the actual emitted DAG, not this estimate.

## Runtime ports, compatibility and implementation order

The present compiler lowers every `{id,value,type}` input to a literal, stores type/unit/thought in a companion contract, and checks numerical refinements by executing its sample values. `K.run(graph,overrides)` replaces literal values and returns a different resolved graph. It does not enforce the companion type at runtime. Therefore raw literal overrides are neither reusable typed ports nor source-preserving invocation; do not wrap them and advertise a stable port API.

New `input` declarations, all types/refinements, recipe constants, provenance policy and registry identity must be inside recoverable source. Invocation supplies exact name->value bindings plus external provenance snapshot metadata; missing optional observation is explicit null or a typed row absence, never a missing required binding. Same source + different invocation can change output but cannot change emitted source or either genome. Changing a literal/policy constructs new source identity. Constructor reproduction checks must succeed without observations; task execution requires bindings. Repeat occurrence is part of the run record, not permission to resubmit a proposal.

Do not retrofit the existing graph `version:1` to silently admit new ports. Follow the semantics specialist's new envelope/profile discriminator; existing task/source bytes remain executable only under the experimental legacy registry. Preserve old literal override fixture API there. Stable migration makes current supplied examples authored literals by default; changing them into runtime ports is an explicit author decision. Stable admission rejects unknown fields and enforces types uniformly through builder/import/core/runtime. Types inferred from one sample are drafts requiring review, especially empty collections and domain units.

Implement in this order: source/runtime separation and shared validator; seven additions with negative fixtures; five recipe builders whose expanded DAGs remain inspectable; golden source and old 53-fixture compatibility checks; browser/Node parity and repeated source-preservation checks. Stop before any adapter. Acceptance must include absent binding/type mismatch, no eligible result, stale/future evidence, duplicate provenance, dynamic divisor failure, overflow, pending/unknown receipt, exact terminal deduplication and same-source/two-snapshot quine identity. Do not claim registry freeze or tested new recipes until these tests run against the production implementation.
