# Independent recipe correctness audit

Scope: all ten records in `qdl-v1-library.js`, public `compile`/`execute` execution, operation implementations and input schemas. Read `AGENTS.md` and `docs/PROGRAM-CONTRACT.md`. Changed no pinned runtime, registry, recipe or release assets. Node v26.10.0, 2026-10-04.

## Evidence and conclusion

`node verify-v1-library.cjs` passes all 44 shipped fixtures (39 completed, three admission refusals, two failed evaluations). `node research/website-overhaul/sol-audit.cjs` independently passes 50 hand-calculated cases (38 completed, 12 domain failures/refusals). It checks different producer inputs, not only fixture selection, plus invalid domains. The independent script uses explicitly authored expected answers rather than calling the implementation to generate expectations. The overflow diagnostic was initially hypothesized as `overflow`; actual checked runtime code is `nonfinite`, now explicitly asserted.

All ten programs have at least two distinct successful outputs for distinct inputs. Backward traversal from exported outputs finds **zero dead nodes**, including all constants and all runtime input ports. Structural liveness does not imply every edit affects every output: Boolean gates, freshness filters, floors, resource minima and source deduplication intentionally create plateaus. No arithmetic or fixture correctness bug was demonstrated. Real-world usefulness and caller authenticity remain narrower than the attractive agent names might suggest.

## Actionable product issues, with exact boundaries

1. **The old gallery teaches a different input model.** `gallery.js` `literalGraph()` applies fixture overrides to source literal parameters and `rebuild()` regenerates program/genome. A legacy fixture change therefore changes program source identity. For the new ten-recipe demo compile once, execute repeatedly with named bindings, and show invariant sourceHash beside changing inputHash, outputs and trace. Do not present a changed literal graph as the same source receiving an observation.
2. **Show causal execution, not a generic animation.** The above table supplies changes that traverse different rules or alter intermediate values. Render the actual returned nodeId/op/input/value trace. Highlight the affected chain and use explicit baseline/changed output deltas. Creature anatomy can remain constant while invocation state changes. A source-preserving run is a stronger demonstration than a pulsing sprite.
3. **Most current Boolean outputs hide why a proposal skipped.** Gather exports proposal/ready but six anonymous booleans; trade exports all-zero quote for several different failures; triage exports skipped/empty string. The existing trace contains eligible, fresh, hasStock, withinAllowance, found, hungry and chosenId, so the website can explain causes without changing frozen recipes. Label checks as skill, route, reservation, capacity, owner permission, remaining uses in that exact order.
4. **`current` is caller testimony about freshness in route/triage.** Unlike gather/evidence, these recipes compute no observation age. Display “caller marks snapshot current” and allow that checkbox to visibly gate proposals. Do not call this a verified freshness window.
5. **Triage may propose a useless meal.** The input admits restoration 0 and selection only checks edible/fresh. Executed singleton `{id:'zero',edible:true,fresh:true,restoration:0}` with hunger4/currenttrue: simulated eat-proposal payload zero, ready true. This follows the advertised selection rule but does not establish hunger reduction. Show restoration with the candidate, and describe the recipe as candidate selection; a future newly authored recipe could require restoration>0 or report predicted remaining hunger. Preserve pinned recipe.
6. **Routes admit inconsistent neighbor maps.** Streets record declares exactly A/B/C/D, but neighbor arrays are arbitrary strings; A:['E','B'] is accepted and E is a dead end. This is not an incorrect BFS result, but no closed-map validation is performed. A demo editor should explain or validate A–D neighbor choices before execution, while preserving raw-output honesty.
7. **Evidence authenticity and independence are caller obligations.** Renaming the same physical sensor to distinct source strings can inflate support counts; adding repeated same-source observations does not. Fresh timestamps and revisions are also supplied, not authenticated. Show provenance rather than claim consensus truth. Same-source true/false remains conflict, which is correctly conservative.
8. **Work schedule is an uncapacitated dependency estimate.** It performs no workstation allocation, resource reservation, or real duration measurement. Its stable order ['a','b','c'] can list b (start3) before c (start0); visualize actual start/end intervals rather than claim serial dispatch order.
9. **Receipt reconciliation validates histories, not external actions.** Unknown or pending blocks retry advice, and repeated acknowledgements cannot inflate units. The function does not submit retries. Show partial confirmed units and attempt timeline; label mayRetry as advisory. The validator can fail even for irrelevant-operation rows with malformed units, because row validation precedes operation filtering; avoid claiming it ignores all malformed foreign history.

## Reproduction

Run both read-only audit commands from repository root:

```sh
node verify-v1-library.cjs
node research/website-overhaul/sol-audit.cjs
```

The second prints explicit case outcomes plus per-recipe runtime inputs and dead-node results. There is no generated acceptance artifact or release-file mutation. Runtime domain refusals are exceptions before a run exists; failed evaluations return a run with diagnostic and cleared outputs/effects. Website presentation must distinguish those states from ready=false or a skipped local proposal.
